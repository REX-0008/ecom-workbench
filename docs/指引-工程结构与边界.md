# 指引 · 工程结构与边界

> 从 [插件根 AGENTS.md](../../AGENTS.md) 迁出（2026-10-17，Step 5 的 AGENTS.md 瘦身）。
> **迁出理由**：它讲「东西该放哪、谁跟谁是一对」，只在**新增文件 / 判断该改哪一侧时**才要看。

## 三者的边界：节点 / 工作流 / 采集脚本

这是本项目最容易搞混的一条。**判据是一句话：改这件事，要不要动 `src/`？**

| 东西 | 住在哪 | 改它要动什么 |
|---|---|---|
| **节点**（可复用的积木） | `src/nodes/<类>/<名>/node.ts`（**定义**，纯数据）+ `src/nodes/impls.ts`（**实现**，只宿主半引） | 动 `src/`，然后 `npm run bundle` |
| **工作流的执行模型**（调度、变量、拓扑、存档） | `src/workflow/` | 动 `src/`，且必须跑 `run-graph` / `loop-plan` / `workflow-doc` |
| **具体某条采集工作流**（抖音表单下载 / 天猫取数 / 巡查…） | **不在 `src` 里** —— 是 `scripts/browser/build-*.mjs` 生成 → 存成 JSON 存档 | **只动 `scripts/` 与存档，不动 `src/`** |

⚠️ **这条边界的实际后果**（别去 `src` 里找某条工作流）：
「修抖音工作流的某个 URL」改的是 `scripts/browser/douyin-code.mjs`，
然后重新生成存档；`src/` 一个字都不用改。

⚠️ **为什么节点定义与实现分开**：客户端要用节点定义渲染节点库与表单，
而实现里会 import Node 内置模块（`node:fs` 等），打进客户端体积且毫无意义。
所以 `src/nodes/index.ts` **只导出定义**，实现表在 `src/nodes/impls.ts`。
`nodes-layout` 测试会查「定义文件不许 import Node 内置模块」。

⚠️ **`flow.loop` / `flow.workflow` / `flow.start` / `flow.end` 四个节点不在 `NODE_IMPLS` 里** ——
它们由**调度器解释执行**（`src/workflow/run.ts` 的 `runSeq` 里分派）。
放进实现表反而会被当普通 builtin 去派发、找不到实现就报错。

## 加东西要改哪几处（汇总点只有这几处）

| 加什么 | 要改的处 |
|---|---|
| **一个节点** | ① `src/nodes/<类>/<名>/node.ts`；② `src/nodes/index.ts` 的 import + `NODE_LIBRARY` 数组；③ `tests/nodes-layout.mjs` 的 `EXPECTED` 与计数 |
| **一条采集工作流** | ① `scripts/browser/build-*.mjs`；② `node scripts/build-patrol-workflows.mjs` 重新生成存档；③ 真机跑一次 |
| **一个工作流引擎能力** | ① `src/workflow/run.ts`（跑法**只此一份**）；② `tests/run-graph.mjs` 加断言 |
| **一个客户端界面** | ① `src/client/workbench/*.tsx`；② `npm run bundle`（测试读产物）；③ `tests/dom-render.mjs` 加断言 |

## 目录规范

| 目录 | 放什么 | 命名 |
|---|---|---|
| `docs/` | **长期有效的知识**：怎么运作（`机制-`）、照着做（`指引-`）、外面的世界（`调研-`） | `中文分类-文件名.md`，**无日期前缀** |
| `plans/` | **一次性的方案与台账**：总纲、执行记录、决策清单 | 见下 |
| `pitfalls/` | **踩坑与避坑** | `<主题>.md`，无日期前缀，按主题分文件 |
| 插件根 | **结论与规则** | `设计计划.md`、`节点说明与参数规范.md`、`AGENTS.md` |

**「我们打算怎么做」→ `plans/`；「出事了怎么办」→ `pitfalls/`。两者都不进 `docs/`。**

### plans 的命名

| 任务类型 | 命名 |
|---|---|
| **复杂任务**（属某大任务，有层归属） | `<任务名>-YYYY-MM-DD-<执行序>-<层>-<名字>.md`；执行序两位 |
| **单项任务**（独立一件事） | `YYYY-MM-DD-<名字>.md` |
| **非层级子项**（属大任务但不属某层） | `<任务名>-YYYY-MM-DD-<执行序>-<用途>-<名字>.md` |
| **例外**（长期滚动维护） | `<任务名> · 总纲.md`、`<任务名> · 进度记录.md` |

**判为复杂但还没立总纲时，先立总纲再挂子计划。**

⚠️ **总纲里的进度记录搬到单独文件**（用户 m00789 定案）：
`plans/电商AI工作台 · 进度记录.md`，总纲里只留一行链接。
搬的时候**逐条搬、不删** —— 进度记录是决策的来龙去脉。

## 代码注释里的路径怎么写

**用目录内相对路径**，不指向工作区其他位置（如 `docs/机制-…md`，不写 `../../docs/…`）。
