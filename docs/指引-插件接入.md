# 指引 · 插件接入（给写插件的第三方）

> 状态：**v2**，2026-10-21。目标不是通用性，而是**让别人能方便地接进来**。
> 板块注册机制已落地（`src/client/workbench/board-registry.ts`），本文与它同步；
> 节点注册（第四节）仍是草案。接口一旦定稿只在末尾记变更，不回改前面的例子。

## 一、你能接什么

两样东西：

| 接入项 | 你得到什么 | 你提供什么 |
| --- | --- | --- |
| **板块** | 左栏出现一个入口，点开是你的界面 | 一个 React 组件 + 元数据 |
| **节点** | 画布节点库里出现你的节点，能拖上画布、能跑 | 一份节点定义 + 一个执行函数 |

**板块与节点是两件事**，可以只接一样。但常见组合是**两样一起**：
你想做一个「素材下载」板块，通常也要一个「下载素材」节点给它用。

## 二、接入前必须知道的三条硬约束

### 1. 你的界面会被打进同一个运行时，出错会拖垮工作台

我们**不用 iframe 隔离**（照 `dock-base` 的做法：注册时直接传 React 组件）。
好处是快、样式统一、没有跨窗口通信；代价是**你的组件抛错会白屏整块界面**。

**所以：每个注册的板块外面，我们会强制包一层错误边界。**
你的组件出错时那块显示成「这个板块出错了 + 重试」，其余板块照常。
但请你自己也守住两条：

- **不要在渲染期做副作用**（fetch、改全局变量）；
- **不要假设自己拿得到 `window.dshDesktop` 之类的东西** —— 用之前判存在（这是本项目白屏的第二大成因）。

### 2. React 版本必须与我们一致：18

不是 19。dsh 客户端是 18，Langflow / Activepieces 那两个参考项目都是 19，所以搬不过来。
你的组件按 18 写，`forwardRef` 该用就用（19 允许 ref 直接当 prop，18 不允许）。

### 3. 样式用我们的令牌，不要自己定义颜色

- 底色 / 文字 / 边框：`--dsw-alias-*`（dsh 语义层，亮暗两套值自动跟随主题）；
- 字号：`--dsh-content-font-size`（正文，跟随用户设置）；
- 圆角 / 间距 / 阴影：从 `src/client/styles/tailwind.css` 的 `@theme` 里取，**不写任意值**。

⚠️ **Tailwind 不引 preflight，盒子模型默认不是 border-box** —— 我们已在自己的容器上补了作用域重置，
你的组件挂在里面就能用；挂外面要自己处理。

## 三、注册板块

### 形状

```ts
interface BoardRegistration {
  id: string              // 唯一，建议带前缀：'myplugin.materials'
  title: string           // 左栏显示的名字（也用作面包屑与标题）
  icon?: BoardIcon        // 组件、{ path: 'M…' } 的 SVG 路径，或任意现成节点（emoji）
  order?: number          // 排序，小的在前；省略 = 100
  group?: string          // 侧栏分组名（可选；同名相邻的归一组）
  tabs?: readonly BoardTab[]  // 板块内的 tab；省略 = 不画 tab 条，内容直接铺满
  component: ComponentType<BoardProps>
}

interface BoardTab {
  id: string              // 只需在本板块内唯一
  label: string
  keepMounted?: boolean   // 这一格一旦打开过就一直挂载，切走只藏起来（不卸载）
}
```

`BoardProps` 给你的：

| 字段 | 含义 |
| --- | --- |
| `active` | 当前板块是不是正显示着。**不是就别轮询**（省资源） |
| `tab` | 用户在本板块选了哪一格（没有 tab 时为空串） |
| `apiBase` | 我们插件的路由前缀，拼你自己的接口用不上，但取数/巡查的数据在这里 |
| `topHidden` / `onToggleTop` | 顶部（面包屑 + 大标题）收起状态与切换 |
| `onSelectTab` | 切到本板块的某一格（比如「打开到画布」那种跳转） |
| `onRunWorkflow` | 直接跑一份工作流（传工作流名），你的板块不必自己写跑法 |

### 注册与清理

```ts
ctx.effect(() => ctx.ecomWorkbench.registerBoard({
  id: 'myplugin.materials',
  title: '素材',
  component: MaterialsBoard,
}))
```

`registerBoard` 返回**反注册函数**，交给 `ctx.effect` —— 插件停用或热更新时自动摘掉。
不交的话热更新后会出现两个同名板块（注册表对同 id 重复注册按「替换」处理，那是兜底、不是正路）。

### 先分清是哪种插件：两条路的门槛不一样

`ctx.ecomWorkbench` 这个服务由 ecom-workbench 自己 `provide`（`src/client/index.ts:311`）。
第三方能不能读到它，取决于插件是怎么装进来的：

| 装法 | 加载路径 | 读 `ctx.ecomWorkbench` 要什么 | 出处 |
| --- | --- | --- | --- |
| 动态插件（在 dsh 界面里让 Agent 现场装的） | 经 `dynamicCordisContext` 守卫门面 | 必须在 `inject` 里声明。不声明会被守卫拒，报错原文：`service "ecomWorkbench" is not declared by your plugin` | `cordis-client-runner/src/client/guard.ts:195`（`declared = new Set(Object.keys(ctx.fiber.inject))`）、`:211`（`if (requireDeclaration && !declared.has(name)) return denyRead(name)`） |
| profile 插件（写进 `profiles/<profile>/package.json` 的 `dsh.profile.bundles`、由宿主进程加载） | 原生 cordis，不经门面 | 只要宿主已经 provide，直接读属性即可；宿主还没 provide 时读会抛 `cannot get property "ecomWorkbench" without inject` | `vendor/cordis/src/reflect.ts:144`（那句报错的生成处）、`:140-142`（已存在则直接给） |

两条路都写 `export const inject = ['ecomWorkbench']` 是最省心的写法，写了两边都对。区别只在「不写会怎样」：

- 动态插件：直接被拒（守卫一层，报错清晰）
- profile 插件：宿主已 provide 时不写也能读到；宿主未 provide 时抛错
- profile 插件还有一处差别：没在 `inject` 里声明的插件不会因服务后到而重新执行 ——
  实测未 provide 时装上、之后 provide，`apply` 只跑了一次、没有被唤醒（原因见 `reflect.ts:152-166`：
  只有 `prop in fiber.inject` 那条路才会挂起等待）。所以要读一个可能后到的服务，仍然要声明。

三种读法实测（原生 cordis，宿主已 provide）：

```
不 inject 读属性 → 读到 function
不 inject 走 ctx.get('ecomWorkbench') → 读到 function
inject 之后读属性 → 读到 function
```

`ctx.get(name)` 那条在两条路上都不看声明（守卫里 `get` 传的是 `requireDeclaration=false`，`guard.ts:222`），
代价是要自己判 `undefined`。它适合「有就用、没有就算了」的可选能力；板块注册是硬需求，用 `inject` 更直接。

### 不交反注册函数会怎样（实测）

```
① 不交反注册 → 注册后板块存在: true
① 插件停用后仍然存在: true        ← 残留
交了反注册的那次: 停用后板块数回到 0，不再存在
```

也就是说：「不交给 `ctx.effect`」的后果不是「可能出问题」，而是停用后那个板块一定还在。
热更新时注册表虽然按同 id 替换（不会叠两块），但那只是兜底 —— 停用不掉的板块会一直留在左栏。

### 排序与常驻

- **顺序靠 `order`**：八个默认板块是 10 / 20 / … / 80，插到中间就给个中间值。
- **`keepMounted` 是声明，不是特例**：画布那一格靠它在注册项里声明「切走也别卸载」。
  骨架不知道哪个板块是画布 —— 它只读这个字段。你要做「切走不丢状态」的界面，同样这么声明。
  ⚠️ 代价：常驻的块在后台一直挂着，别在里面轮询（看 `active`）。

### 出错会怎样

**每个注册的板块外面强制包一层错误边界。** 你的组件渲染抛错时：
只有你那一块显示「这个板块出错了 + 重试」，左栏与其它板块照常可用。
（这条有测试盯着：`tests/board-registry.mjs` 会临时注册一个会抛错的板块真挂一次。）

### 默认板块

我们不写死任何板块。工作台的八个默认板块（总览 / 取数 / BI / 定时 / 提醒 / 内容 / 工作流 / 收藏）
**也是用同一个 `registerBoard` 注册进去的** —— 没有特权通道。
所以你增减板块、改顺序，都只是注册表变，不动骨架代码。
（骨架文件 `EcomWorkbench.tsx` 里搜不到任何板块 id 字面量，有测试盯着这条。）

## 四、注册节点

节点分**两半**，这是本项目最重要的一条设计：

| 半 | 是什么 | 谁用 |
| --- | --- | --- |
| **定义**（`NodeDef`） | 纯数据：id / 名字 / 端口 / 参数表 / 说明 | 客户端渲染节点库与表单；宿主半也读 |
| **实现**（函数） | 真正干活的那段代码 | **只在宿主半跑** |

分两半的理由：定义要给界面用，不能 `import('node:fs')` 这类东西；实现会拉进 Node 内置模块，
打进客户端毫无意义。

### 定义长什么样

最小的节点定义：

```ts
const NODE: NodeDef = {
  id: 'myplugin.fetch-assets',
  label: '下载素材',
  summary: '把商品主图与详情图下到本地',   // 画布上显示，**不超过两行**
  executor: 'builtin',                     // 见下表
  inputs:  [{ id: 'in',  label: '商品', type: 'data' }],
  outputs: [{ id: 'out', label: '文件', type: 'data' }],
  onError: 'stop',
  params: { dir: '' },
  paramDefs: [
    { key: 'dir', label: '保存到', kind: 'text', hint: '留空用工作台的默认素材目录' },
  ],
}
```

**`hint` 是必填的**，常显在输入框下方（不藏在悬停里）—— 这是我们的硬规范：
用户不该为了知道一个参数填什么而先把鼠标悬上去。

### 五种执行方，选哪个

| `executor` | 什么时候用 | 你的实现是 |
| --- | --- | --- |
| `builtin` | **推荐**。要读文件、算东西、调进程 | 注册一个函数（见下） |
| `shell` | 你已经有现成脚本（bat / sh / python） | 一段拼命令的逻辑 |
| `http` | 调外部接口 | 不用写，填 URL 就行 |
| `agent` | 要模型参与（写文案、做判断） | 不用写，给 prompt |

⚠️ 简单说：**碰外部世界（文件/网络/进程）用专用执行方，只吃上游吐下游用 `code.js`**。
拿不准就问：这段逻辑里有没有 `import('node:fs')`？有就不是纯计算。

### 实现怎么注册

```ts
ctx.effect(() => ctx.ecomWorkbench.registerNodeImpl(
  'myplugin.fetch-assets',
  async (command, ctx) => {
    // command = { node: id, params: {...} }
    // 返回值就是下游拿到的输出
    return { files: [...] }
  },
))
```

实现里能拿到的 `ctx`：工作目录、取消信号、以及一个「起子进程」的入口。

**也可以不注册实现** —— 如果你的节点走 `shell` / `http` / `agent` 执行方，
调度器会自己拼命令去跑，你什么都不用写。

### 三种接入形态（按对方是什么选）

| 你是 | 怎么给实现 |
| --- | --- |
| **dsh 插件**（推荐） | `registerNodeImpl` 直接给函数，同进程，最快 |
| **外部程序 / 脚本** | 不用给实现：节点声明 `executor: 'shell'`，你的脚本路径写进参数 |
| 远程服务 | 用 `http` 执行方，填 URL |

**我们不支持**：别的进程里注册一个「远程函数」当实现。那需要你常驻一个服务，收益不值得。

## 五、写工作流（给接入者看的部分）

工作流是画布上的图：**节点 + 连线**。存档是一份 JSON。

### 三条必须记住的规矩

1. **输入靠开始节点，输出靠结束节点**。
   没有开始节点 = 这份工作流**接不了外部输入**（不是「把参数发给第一个节点」，我们不接受这种兜底）。
2. **循环要么放框里，要么不是循环**。循环是容器，`parentId` 决定归属。
3. **变量用 `{{名字}}`**。取上游某节点的字段用 `{{节点id.字段}}`；嵌套循环里往外一层用 `{{outer.item}}`。

### 能直接用哪些节点

| 分类 | 节点 | 干什么 |
| --- | --- | --- |
| 浏览器 | `browser.act` | 一个节点 + 动作下拉：打开页面 / 点击 / 输入 / 取文本 / 截图 / 执行脚本 |
| 浏览器 | `browser.download` | 点一下触发下载并落盘（**触发 + 等待 + 保存必须在同一节点**，CDP 下的硬约束） |
| 代码 | `code.js` / `code.python` / `code.shell` | 写一段代码。**碰文件系统请用专用节点，别在 code.js 里 import('node:fs')** |
| 终端 | `sys.fs.read` / `sys.fs.write` / `sys.http` | 读写文件、发 HTTP |
| 流程 | `flow.start` / `flow.end` | 入口 / 出口 |
| 流程 | `flow.if` | 条件分流（两条出口，未走的那条及其下游不跑） |
| 流程 | `flow.loop` | 循环容器 |
| 流程 | `flow.merge` | 多路汇合 |
| 流程 | `flow.workflow` | 跑另一份工作流 |
| 流程 | `flow.delay` | 等一会儿 |
| 数据 | `data.map` | 批量变换 |
| 电商 | `ecom.*` | 取商品 / 改 SKU / 拉订单 / 生图 / 生成文案 |

### 判断「该不该做成工作流」

见仓库根的 `AGENTS.md`「什么该做成工作流（七问）」—— 那是我们自己的判据，你接进来时同样适用。

## 六、最小可跑的例子

一个插件，同时注册一个板块和一个节点：

```ts
export function apply(ctx: Context) {
  // ① 节点定义（纯数据）
  ctx.effect(() => ctx.ecomWorkbench.registerNode({
    id: 'myplugin.hello',
    label: '打招呼',
    summary: '把上游的名字写成一句话',
    executor: 'builtin',
    inputs:  [{ id: 'in', label: '名字', type: 'text' }],
    outputs: [{ id: 'out', label: '句子', type: 'text' }],
    onError: 'continue',
    paramDefs: [],
  }))

  // ② 节点实现
  ctx.effect(() => ctx.ecomWorkbench.registerNodeImpl('myplugin.hello', async (cmd) => {
    const name = String(cmd.params.name ?? '世界')
    return '你好，' + name
  }))

  // ③ 板块（只有客户端半有界面）
  ctx.effect(() => ctx.ecomWorkbench.registerBoard({
    id: 'myplugin.board',
    title: '我的板块',
    component: () => null,
  }))
}
```

## 七、现在还没有的（别依赖）

如实列出，免得你照着写却用不上：

- **跨插件的数据共享**还没有标准形状 —— 目前只能各自存各自的；
- **节点的「缺依赖 → missing 态」**是空壳（状态定义在，检测逻辑没写）；
- **并行节点 / 暂停恢复**正在做，接口可能变；
- 板块**内容组件目前不支持懒加载**（`component` 必须是同步组件），后面可能放开。
