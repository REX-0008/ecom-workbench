## 怎么跑

**别在文档里维护精确的测试清单**（会过期，已经过期过几次）——
用 `node scripts/run-tests.mjs` 跑全部，它会**自动判**每个测试要不要 tsx loader。

判据（`scripts/run-tests.mjs` 里的 `needsTsx`）：文件里有没有
`from '../src/` / `from '../scripts/` 这类**真 import**（注释里提到的不算）。

```
node scripts/run-tests.mjs          # 跑全部，只报结果
node scripts/run-tests.mjs -v       # 逐个报
node scripts/run-tests.mjs dom-render loop-box   # 只跑点名的
```

⚠️ **`npm test` 会超工具的单次 120 秒上限**，所以要跑全套时用 `run-tests.mjs` 放后台。
单个测试直接跑即可，例如：

```
node tests/dom-render.mjs                        # 纯 node 的那种
node ../../refs/deepseek-harness@62962ee4/node_modules/tsx/dist/cli.mjs tests/run-graph.mjs   # 要 loader 的那种
```

## 读源码还是读产物

这条最容易踩：**读产物的测试，改完源码必须先 `npm run bundle`，否则测的还是旧产物 = 白验**。

| 读产物（要先 bundle） | 读源码（不必 bundle） |
|---|---|
| `dom-render`（`lib/client.js`）| `refit-base` |
| `loop-box`（`lib/client.js`）| `browser-driver`（`src/nodes/browser/driver.mjs`）|
| `host-dispatch`（`lib/index.js`）| `douyin-logic` / `tmall-logic` / `douyin-workflow` 等 |
| `bundle-identifiers` / `browser-two-layers` / `css-refs` | |

⚠️ **改了 `src/nodes/browser/driver.mjs` 也要 `npm run bundle`** ——
它靠 `scripts/copy-runtime.mjs` 复制进 `lib/`，不复制的话**部署目录里还是旧脚本**
（真机上表现是「改了没生效」）。

⚠️ **`npm run bundle` 会把产物同步到部署目录**（`scripts/deploy.mjs`）：
插件在 profile 里是 `file:` 依赖 + `nodeLinker: hoisted` = pnpm 把插件**复制**一份，
所以「源码目录的 `lib/`」与「桌面端实际读的那份」是**两个文件**。
只跑构建不同步的表现是「代码改了、测试全绿，界面上就是没有新东西」
（踩过两次，见 `pitfalls/改了代码桌面端没变化.md`）。

## 安全网：别删那几条指纹断言

`ingest-workflow` / `tmall-workflow` / `douyin-workflow` / `patrol-workflows` 里有
「跑完比对真实 `原始数据` 目录的大小与 mtime」的断言。那是**安全网**：
2026-10-14 曾因「测试只换了一处路径」而**把测试数据写进真实库**
（见 `pitfalls/测试误写真实数据库.md`）。**别删**。

`collect` 走收藏的逻辑层（扫描 / 备注 / 搬移），全程在 `EWB_TEST_HOME` + `EWB_TEST_SKILLS`
沙箱里 —— **不设后者就会去动真实的 `$DSH_HOME/skills`**，那是红线。

## 几个测试各自盯什么

### `dom-render`（客户端整体渲染）

**唯一覆盖客户端整体渲染的测试**，改任何 `src/client/` 文件都要跑它。
它给全局挂 `fetch` 桩模拟宿主半，从而能断言数据行；`hasCanvas === true` 这类断言覆盖不到界面。

末尾有三条回归断言（画布仍挂载 / 真的看不见 / 不抢全局键盘），都验证过有效性：
改回旧写法会直接失败。

### `loop-box`（循环框点了有没有用）

它存在的理由是一类 **「回调有被调用、但用户什么变化都看不见」** 的 bug ——
用户原话是「循环的收起展开**没有实际作用**」「设置还是无法打开，点击没有作用」。
所以判据一律按**看得见的效果**定，不按「函数被调了」定：
① 收起 → 框**缩成一条**（46px）**且**循环体成员**从画布上消失**；
② 设置 → 面板**真的出现在画布上**且框**为它长高**（不长高的话面板溢出框外，看起来还是「没反应」）；
③ 框宽不是旧的两个节点宽。

⚠️ 它必须用**一份带 `parentId` 的存档**（框里真有一个成员）—— `dom-render` 那段是
「往空画布加个空循环」，成员该不该被藏在那里**无从判起**。
第一版在 `dom-render` 里拿「除框以外随便一个节点」冒充成员，那是画布上的普通节点、
不该被藏 → 断言必然红（**假红**）。归属只能按 `parentId` 判。

⚠️ 它**必须先轮询等框有尺寸再断言**：打开存档后要跑一次自动布局，固定延时不够时
`dim('height')` 读出来是 0，「收起后缩成一条」会**假红**（0 → 46 看着像变大了）。

### `height-chain`（高度链与滚动）

从工作台外壳一层层到节点展开区，每层该有 `min-height: 0` / `overflow` 的都得有。
它盯的是一类**静默失效** —— 构建通过、单测通过、真机上「内容被压没且不出滚动条」。

⚠️ 其中有一条专门说清一条 flexbox 规矩：**flex 子项的 `overflow` 不是 `visible` 时，
它的「自动最小尺寸」算作 0**，也就是**它成了唯一可被压扁的子项**。
`.detailBlock` 为圆角带了 `overflow: hidden`，于是被压到 0 高、内容永不溢出、
滚动条永不出现 —— 两个症状同一个原因。修法是滚动容器里的子项 `flex: 0 0 auto`。
**在滚动容器里加子项时，先确认它不会被压扁。**

### `css-refs`（类名有没有对应规则）

在**产物层**核对类名有没有对应规则 —— 专抓「构建通过、单测通过、真机上样式失效」这一类。

### `elk-layout`（自动布局排出来的形状）

用两个方向的**长宽比对比**，不是「纵向必须高>宽」。曾因端口 id 重名而退化成方块，
不报错、不崩、也不影响别的测试。

⚠️ 那条判据 2026-10-11 改过：节点宽度 218→300 后纵向同层并排就 600px 起，
「高>宽」不再成立，而旧写法等于把「节点不能太宽」偷偷编进了断言。改判据前先确认它仍抓得住那个 BUG。

它还盯着另外两条**静默失效**（都踩过，都不报错）：
① **间距必须跟节点宽度成比例** —— 曾经写死 90px，而节点从 218 加宽到 300 后没跟着调，
   比例从 0.41 掉到 0.30，用户就看出来「间隔太近」了；
② **量尺寸必须除掉画布缩放** —— `getBoundingClientRect()` 是屏幕尺寸，
   不除掉的话缩到 50% 时 ELK 按「一半宽」排，节点**真的会重叠**。

### `group-roster` / `group-ops`（编组的名单模型）

`group-roster` 钉 **n8n 的 Canvas Groups 模型**。关键几条：
① 框的位置是**算出来的**（`groupBox`），**成员坐标一个都不许被改写** ——
   新模型的安全性全靠这条（旧模型那族「框跳走 / 贴边覆盖 / 坐标互转错」的 bug 由此消失）；
② **一个节点最多属一个组**（n8n 硬规则），加进新组时要从原组摘掉；
③ 拖动框 = 给成员加**同一偏移**（`moveGroupBy`），非成员**一点不动**；
④ 无变化时返回**原数组引用**（幂等，调用方据此跳过 setState）；
⑤ 描述超长**截断**到 145 字（照 n8n），不是拒绝。

`group-ops` **现在只剩连贯规则**（`closeUnderTransit`）—— 坐标换算那批函数
2026-10-13 随名单模型一起删了。它钉的是「夹在中间的节点自动纳入」：
判据是「**有没有上游在集合里**」+「**能不能走到集合里的下游**」，
**两个条件缺一个都会坏**：少了前者会顺着链把整张图吞进来，少了后者则中间隔几个就漏。
那个算法被自己的测试抓出过两次错，改这两个条件前先确认它仍全绿。

### `run-graph`（共用的调度语义）

钉住**顺序 / 跳过 / 失败策略 / 环 / 带不带上游 / 循环 / 分支**。
⚠️ **它是画布与宿主半唯一的一份跑法**（2026-10-11 合并完成）：
两边都调 `runGraph`，各自只负责「翻译输入」与「把事件画出来 / 写记录」。
所以**改跑法语义只需改这一处** —— 别再分叉出第二套。

`includeUpstream` 那个开关区分「只跑这个」（false）与「从这里跑」（true），
两者**语义不同别合成一个**（历史上它们曾传同一组参数，导致「只跑这个」偷偷带上游）。

### `run-specs`（图 → 调度器规格的翻译只有一份）

⚠️ 这个字段曾经**写了两份**（画布自己一段 `map` + 宿主半的 `toRunSpecs`），
漂了两次：画布那份漏 `parentId`（循环体不被认出来 → `{{item.url}}` 原样发给浏览器）
与漏 `sourceHandle`（**未走的分支照跑**）。
**判据是「两种来源翻译同一张图必须逐字段同构」**，另逐条钉住易漏字段。

⚠️ 四条端到端测试（`douyin-workflow` / `tmall-workflow` / `ingest-workflow` /
`patrol-workflows`）**必须走 `toRunSpecsFromCanvas`，不许自己拼一份映射** ——
它们原先各自手写，于是「一直在测自己那份」，画布那段真实代码从没被跑过
（测试全绿而功能是坏的）。详见 `pitfalls/同一件事写两份迟早漂.md`。

### `workflow-doc`（存档往返）

钉**存档往返**：容器归属、**编组名单**、**旧档迁移**、脏数据、手写类型字段（`types`）。

⚠️ 它守着一个**曾经的缺陷**：分组框 `defId` 是 `__group`、不在节点库里，
读回时被判「缺类型」丢弃 → **编组保存后重开就没了**
（当时按 `type` 合成占位定义修掉）。**2026-10-13 之后分组框不再是节点**，
这条换成**旧档迁移**：读旧档时把「`type: group` 的框 + 子节点的 `parentId`」
**迁成 `nodeGroups` 名单**，做三件事（少一件就坏）：① 成员坐标 **相对→绝对**；
② 摘掉 `parentId`；③ 分组框那个**节点**从图里去掉。
⚠️ **只迁 `group`，不迁循环** —— 循环仍是 `parentId` 容器。这条**必须**测，
而且测试里**要同时放一个分组框**：迁移只在「有分组框」时启动，
没有框就整段不跑、断言会**永远是绿的**（这个假绿已被「改坏必红」抓到过一次）。

### `env-check`（环境检测的判定逻辑）

它是**「逻辑抽成纯函数」那条规矩的样板**：判定住在 `src/workflow/env-check.ts`
（`buildEnvReport` / `scanNodeGaps`），**宿主半只给机器事实**（它能连 socket、读存档目录）、
**客户端才下结论**（localStorage 里的默认来源/端口只有浏览器看得到）。
所以测它不需要起服务，直接喂构造好的事实 —— 这也是它快且稳的原因。

### `io-fields` / `io-run`（开始/结束节点）

`io-fields` 钉**声明解析**（四列格式、全角分隔符、必填的几种写法、
「没写值」与「写了空值」的区别、**外部多给的字段被丢掉**）。

`io-run` 钉**执行语义**：输入每个节点可取 / 默认值 / **没有开始节点时值没被发给第一个节点**、
两个开始节点抛错 / 结束节点取字段与整体 / **子流程传参**的三种情形。

### `host-dispatch`（宿主半端到端）

路由注册 → 派发 → 内置节点真跑 → 错误路径 → **SSE 运行流**（真起一次 HTTP，
验响应头、`step`/`done` 两种帧、帧格式、`done` 里带 `ran`）。

⚠️ 它跑的是 `lib/index.js`（编译产物）—— 改了源码必须先 `npm run bundle`。

⚠️ **端到端测试抓的是「层间接得对不对」**：2026-10-12 它抓出
`toRunSpecs` 丢掉了 `sourceHandle` → 条件分流的两条边看起来一样 → **未走的分支照跑**。
画布内存里的边是带 handle 的，所以只有「存档 → 无界面跑」这条路会暴露它。

### `nodes-layout`（节点目录化）

盯三件事：① 数量与 id 集合（一个都不许少、不许改 id）；② 目录结构符合约定；
③ 定义文件**不 import Node 内置模块**（否则客户端打包会带上它们）。

⚠️ **加节点要同时改三处**：`src/nodes/<类>/<名>/node.ts`、`src/nodes/index.ts` 的
import + `NODE_LIBRARY` 数组。漏了这里会红 —— 那是**唯一**的汇总点。

### `browser-driver` / `session-color`（浏览器层）

`browser-driver` 钉**不需要浏览器就能测的部分**。真机验证（连真浏览器、开真窗口）
已做过但**不进套件** —— 它要求「用户开着带调试端口的浏览器」，
那种条件不成立时测试就红，而红的原因与代码无关，最后只会被忽略。它盯：
① 七个动作都在；② **绝不杀浏览器进程**（只允许 `browser.close()` = 断连接）；
③ **下载必须先挂监听再点击**（顺序反了会**静默丢事件**，不报错）；
④ 会话登记表自愈；⑤ 报错必须可读（不许抛 playwright 英文堆栈）。
⚠️ 它有 4 条断言第一版写成「查某串存在」，被**注释里**的同一串救活 → 假绿。
现在全部锚到**真实调用**。改它时照此办理。

`session-color` 钉会话色标。⚠️ 它记录了一个实测结论：**6 色板下撞色是鸽笼原理的固有限制**，
换哈希解决不了（试过 FNV-1a / djb2 / djb2+位置权重）。用户已定「就 6 个，允许偶尔撞色」，
所以判据是 ≥4 色 —— **别为了让它变绿去调哈希**。

## 写断言的纪律（`dom-render` 里踩过多次，都留了注释）

- **能在 DOM 上查的，就别在产物里数出现次数**。数 `nowheel` 出现几次曾被 React Flow 自带的
  默认值骗过（它自己就有 4 处）→ 删掉我们的两处它照样通过。改成**真展开节点、查它的类名**。
- **别用 `[class*="wrap"]` 这类模糊选择器** —— 会匹配到 `whitespace-nowrap`。
  找带特定内联 style 的元素，或给一个 `data-*` 锚点。
- **元素引用要每次重查，不能存下来复用**：React 状态一变可能重建这些元素，
  存下来的那个已脱离文档，往它派事件不会冒泡 → 看着像「功能坏了」，其实是测试没连上。
- **改产物验证断言时**：① 注入串**别保留原文**（断言用 `includes` 时替换成 `x原文x` 仍然通过）；
  ② 别往 CSS 字符串字面量里塞真换行（整份产物语法错误）；③ 缩进按**产物**的写法。
  注入不成功时脚本会判 NG，所以不会误报通过 —— 但也就白验了。
- **段落之间要还原现场**：`dom-render` 是一长串顺序执行的断言，
  某段切了 tab 不切回来，后面的段就会看到错误的界面状态而失败（⑧ 段就这么被带崩过一次）。
- **桩里没数据的断言永远绿**：想让「隐藏某个按钮」这类断言有效，
  桩里**必须有**一份会触发它的数据（`dom-render` 就为此专门放了一份 `startType: 'called'` 的工作流）。
- **jsdom 里做不到的事，别在那儿断**：没有 `EventSource` 时面板会立刻退场（那是它该做的），
  所以那儿只断「面板挂上了」，真链路由 `host-dispatch` 的真 HTTP 覆盖。
- **别写死 DOM 层数**（如 `parentElement.parentElement`）：结构一动就静默读到别处的类名。
  要向上逐层找，或用 `data-*` 锚点。
- **不许写「存在才验」**：`if (x !== null) { 断言 }` 在取不到时**一条都不跑也不报错** ——
  而「取不到」恰恰就是「功能没做出来」。一律改成 `if (x === null) errors.push('找不到 x，下面那条没验到') else { … }`。
  2026-10-26 在 `dom-render` 里扫出 5 处，注入验证：前置全取不到 → 全文件 **0 条红**。
  ⚠️ `null !== undefined` 是 `true`，写 `if (x !== undefined)` 会放过 `null`，然后崩在 `null.dispatchEvent` 上。
- **补兜底后「正常运行就红了」，先查位置对不对**：`dom-render` ⑤b 那两条「分组框实例上有描述输入」，
  写在组节点还不存在的位置（组要用户右键打包才创建，那段在 600 行后），**从写下起一次没跑过**。
  存在性问题是结构问题，不是判据问题 —— 把断言挪到元素真正存在的那一段，并在原位置留注释「不移回这里」。
  详见 [假防线](../pitfalls/假防线-看着写了其实不生效.md) ⑦ ⑧。
- **`tests/` 下以 `_` 开头的是共享工具，不是测试**（如 `_wait.mjs`）。没有断言，混进「通过」会让计数说谎。

## 什么时候真跑、什么时候只认证据（核验频率的规矩）

用户 2026-10-27 定：「核验不要太细，一个阶段或者较大内容核验就行了，当前核验感觉太频繁了。」
下面是据此定的规矩。**判据是「这一跑能多排除哪一种可能」，不是「跑得多不多」。**

### 分四档

| 时机 | 谁跑 | 跑到什么程度 |
| --- | --- | --- |
| **单个执行角色自己交付** | 那个角色 | 只跑自己那几组相关测试 + 三查。**贴原始输出，不贴「通过」** |
| **lead 收到单张票的交付** | lead | **只读它贴的证据**：提交号、关键几行的原始输出、`git status`。**不重跑测试** |
| **一个阶段做完**（三五张票同一批收口） | lead | 亲自跑一次这批涉及的**测试分组**，不再逐张复跑 |
| **整批交用户审之前** | lead | 跑一次**全量** + 三查 + `git status` |

### 必须亲自深核的三种情况（不受上表限制）

1. **跨角色地盘** —— 两个角色的改动碰同一批文件，或某角色改了不属于它的路径
2. **不可逆操作** —— 删存档、改存档、覆盖产物、强推
3. **它的报告前后对不上** —— 比如自称「断言一条没删」但条数变少了；或它贴的红行与它的结论互相矛盾

**这三种都是「读它报的东西判断不出来」的，只有自己跑/自己看文件能判。**

### 不要做的两件事

**一、不要每单都自己复跑它跑过的测试。** 角色已经贴了原始输出，重跑一遍得到同一个结果，只花时间不增加信息。它若贴得含糊（只写「全部通过」不给输出），**退回去要输出**，不是自己跑。

**二、不要每单都自己 grep 判据。** 判据该在代码里被断言钉住，不该靠 lead 每次人工核。判据抓不住错 —— 那是**派活时要写清自证**的问题，不是验收时靠人补。

### 反过来：什么时候「跑得勤」是对的

- 改动碰到**读产物的测试**（`dom-render` / `loop-box` / `host-dispatch` / `css-refs` 那几个）—— 每次都得先 `npm run bundle`，这个往返省不掉
- 改**循环、派发、执行语义** —— `loop-plan` 与 `run-graph` 必须一起跑，两个都要
- **自证（注入看红）** —— 这不能省。**「测试全绿」不算自证**，必须是「弄坏了会红」被真跑出来过

## `check:client` 的基线是红的

`npm run check:client` **基线就是红的**（`WorkflowNode.tsx` 的既存类型错），
别把它当改动引入的问题；**有效关卡是 `check:types` 与 `check:tdz`**。

⚠️ **`check:client` 的错数会随「往 `data` 里加字段」增长**（2026-10-12：128 → 152）。
根因在 `types-react-shim.d.ts`：它把 `Node` / `NodeProps` 声明成**非泛型的
`Record<string, unknown>`**，于是每个组件里 `data` 都是 `unknown`。
**这是那个 shim 的既定取舍**（它的作用只是「让解析通过、把 TS2448 那类真错显出来」），
不是新引入的坏代码 —— 加字段只会让同一条错多出现几次。
试过把 shim 改成泛型：总错数反而涨到 171。**要修就得连 React / xyflow 的类型声明一起补**，
那是独立一件事，别顺手做。**判断「有没有引入新错」要按归一化后的消息逐条比，不能只看总数。**
