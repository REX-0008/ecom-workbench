# 机制-节点标签与执行方说明

> 起因：用户 2026-10-14 问「将节点前面和后面的标签有哪些，各自代表什么列一下输出一份到 docs」，
> 并举例问了两个名字分别属于哪一层：`builtin`、以及 `act` / `js` / `delay`。
>
> 本文回答这三件事。写给**不看代码的读者**：每一节先讲「它是干什么的」，再给名称。
>
> ⚠️ 本文**不列节点清单**（节点会加会删，列了必然过期）——
> 只写**怎么分层、每层怎么认**。当前有哪些节点，看画布左侧的「节点库」。

## 一、一个节点上的英文名分三层，不是一回事

看到一堆小写英文（`builtin`、`act`、`browser`）时，先问一句：**它回答的是哪个问题**。
三个问题不同，答案就属于三层：

| 第几层 | 它回答什么 | 在哪看得见 | 取值会变吗 |
| --- | --- | --- | --- |
| **① 执行方** | 「这活**由谁去干**」 | 节点卡片左上角，大写，如 `◆ BUILTIN` | 固定四种 |
| **② 节点类型** | 「这**是哪种**节点」 | 节点卡片右上角的小框，小写短名，如 `act` | 加节点就多一个 |
| **③ 分类** | 「它属于哪**一大类**」 | 卡片顶部那条颜色 / 节点库里的分组标题（中文） | 相对固定 |

**记住这一句就够了**：**执行方说的是「谁干活」，节点类型说的是「是什么」，分类说的是「归哪一门」。**
三者的关系是「多对一」——同一个执行方下有很多节点类型，
同一个分类下也有很多节点类型。

## 二、① 执行方：`builtin` 在这一层

**它干什么**：决定这个节点的活**由谁去做**。
画布自己不做活，它只把活派出去，派给谁就写在这一层。

一共**只有四种**（这四个名字不是节点名，是「干活的方式」）。
下表第三列只是**举几个例子**，不是「谁属于谁」的清单 —— 那个看节点卡片本身：

| 执行方 | 谁去干 | 举几个用它的节点（例子） |
| --- | --- | --- |
| `builtin` | **本程序自己算** —— 不另开小程序、也不发网络请求，直接调一个内置好的功能做完 | 读文件 / 写文件、等待、执行 JavaScript、浏览器-playwright、下载-playwright |
| `shell` | **另开一个小程序**去跑一条命令，跑完收掉 | 执行命令、执行 Python |
| `http` | **向一个网址发一次请求**，把结果取回来 | HTTP 请求、拉订单、取商品、改价改库存、生成主图 |
| `agent` | **交给一个 AI 子代理**去干活 | 生成文案 |

**怎么自己认**：节点卡片左上角那个大写名（`SHELL` / `AGENT` / `HTTP` / `BUILTIN`）
配上图标（`>_` / `✦` / `⇄` / `◆`），就是它在告诉你「这活谁来干」。

⚠️ **一处容易看错的地方**：执行方**不等于「看起来像什么」**。
比如浏览器节点用的是 `builtin`（本程序自己起脚本去连浏览器），**不是 `http`**，
因为它并不是「发一个网络请求」那件事。**以上面那张卡片标签为准，不要凭名字猜。**

## 三、② 节点类型：`act` / `js` / `delay` 在这一层

**它干什么**：告诉你是**哪一种**节点 —— 它有哪些参数、能接什么、能吐出什么。

卡上那个小框里的短名，是**从节点自己的编号里截出来的一段**：
编号里第一个点号**后面**的部分。举例：

| 完整编号 | 卡片上显示的短名 |
| --- | --- |
| `browser.act` | `act` |
| `code.js` | `js` |
| `flow.delay` | `delay` |
| `ecom.copy.gen` | `copy.gen` |

所以「`act` 属于哪一层」的答案是：**它是节点类型这一层的名字，不是执行方、也不是分类**。
同理 `js`、`delay` 都是**节点类型名**。

**这一层有哪些**：答案是「**画布左侧「节点库」里的每一条**」——
那里一条就是一个节点类型，它是唯一不会过期的清单（加节点就多一条，这里就不另抄一份）。

**认名字的规则（这条不会过期）**：完整编号是「**门类.短名**」，
卡片上只显示点号**后面**那截。看编号就知道它属哪一门 —— 举几个例子：

| 完整编号（举例） | 点号前 = 门类 | 卡片上显示 = 短名 |
| --- | --- | --- |
| `browser.act` | `browser` | `act` |
| `code.js` | `code` | `js` |
| `flow.delay` | `flow` | `delay` |

⚠️ **这一层到底有哪些，看节点库**（左侧面板一条一个）。这里不抄一份 ——
抄了就会过期，而节点库永远是当前的。

## 四、③ 分类：决定节点顶部那条颜色

**它干什么**：把节点按「管哪一类事」分组。它**不影响怎么跑**，只影响怎么看 ——
卡片顶部那条横色、以及左侧节点库里的**中文分组标题**，都由它来。

分类是**固定的几门**（中文名就是节点库里看到的那些）：

| 分类名（中文） | 管什么 |
| --- | --- |
| 流程控制 | 条件、循环、等待、合并这类「控制走向」的 |
| 爬虫采集 | 采集入库那一类 |
| 浏览器操作 | 在浏览器里做事 |
| 代码执行 | 跑 JavaScript / Python / 命令 |
| 电商业务 | 拉订单、取商品、改价、生成主图或文案 |
| 终端系统 | 读写文件、发 HTTP 请求 |
| 数据处理 | 字段映射这类 |
| AI 能力 | 用模型做的事 |
| 其他 | 没归类的（兜底） |

对应前面三个例子：`browser.act` 属**浏览器操作**，`code.js` 属**代码执行**，
`flow.delay` 属**流程控制**。

## 五、三层不是一回事：一张对照

| | ① 执行方 | ② 节点类型 | ③ 分类 |
| --- | --- | --- | --- |
| 回答 | 谁来干 | 是哪种节点 | 归哪一门 |
| 有几个 | **固定四种** | 跟节点库一样多 | 固定几门 |
| 举例 | `BUILTIN` | `js` | 代码执行 |
| 会不会随业务变 | 基本不变（这是引擎的四种干法） | 会（加节点就多） | 很少变 |

同一个节点**三层各有一个值**，互不冲突：
「`code.js`」这个节点 = 执行方 `builtin` + 类型 `js` + 分类「代码执行」。

## 六、节点卡片上「前面 / 后面」分别显示什么

⚠️ 这一节是**读代码确认过的**，不是凭印象（依据见文末）。

**卡片顶部那一行，从左到右**：

| 位置 | 显示什么 | 举例 |
| --- | --- | --- |
| **前（最左）** | 图标 + 执行方**大写名** | `◆ BUILTIN` |
| 再往右（只有带「浏览器会话」的节点才有） | 一个**会话色标**：小圆点 + 会话名。**同名 = 同一台浏览器**，同色 | `● shop` |
| **后（最右）** | 节点**类型短名**（第三节那个） | `act` |

**所以「前面」是执行方，「后面」是节点类型短名。** 两者夹着的是节点名与说明（第二行）。

**同一张卡片上还有一处不在这三层里的标签 —— 两侧的端口**（左进右出）：

- 每个端口显示**端口名 + 数据类型**：`any` / `data` / `text` / `image` / `number`，
  颜色由类型定（连线的颜色也跟着源端口走）。
- 打开了「走失败分支」的节点，右侧会**多一个红色的出口**，名字就叫「失败」。

**另外两处会看到同一个名字的地方**（都不是新的一层）：

- **节点库（左侧面板）**每个条目的左上角也有一个执行方标签，
  但那里是**小写**写法（`builtin`）；它与卡片上的大写 `BUILTIN` 是**同一件事**。
- 节点**参数区**里曾经有一排小方块（「执行方 BUILTIN · 成功 · 完成」），
  **2026-10-11 已整排删掉**（用户判定是重复信息）—— 现在那里不再有这些标签。
