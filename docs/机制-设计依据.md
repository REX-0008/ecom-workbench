# 设计依据（2026-10-10）

本项目每个非显然的设计决定，以及它的**理由**。代码注释里用 `依据 §N` 指向本文的编号。

**这是「结论」，不是「调研过程」。** 原始调研在同目录的 `调研-*.md`，
本文是它们的**浓缩与定论**——代码依赖的是本文，需要追根时再翻对应调研。

## 1. 派发器

### 1.1 进程管理走 dsh 自带的 `ctx.subprocess`

`spawn` / `AbortSignal` 取消 / 杀进程树 / 优雅终止 / 超时分类，dsh 都已实现（MIT，base bundle 已注册，第三方插件可 `inject`）。自己写会漏掉孙进程。

**关键点**：`terminate()` 之后**必须 `await waitForExit()`**。只 terminate 会漏掉孙进程——这正是手写 `taskkill /T /F` 无法保证的。

### 1.2 排队走 p-queue，不走 dsh-jobs-local

dsh-jobs-local 的并发上限是**拒绝**而不是**排队**，与我们要的 `queued` 状态语义不符。必须在它前面自己排队。

### 1.3 引擎只决定「谁执行」，不自己执行

这是 dsh 的原生范式。每个节点声明 `executor`（shell / agent / http / builtin），派发器只负责排队与状态推进。

### 1.4 超时 ≠ 被取消

`ctx.subprocess` 的 `timedOut` 与 `aborted` 是**首次原因分类**，两者要分开处理。

### 1.5 HTTP 路由

走 `ctx.inject(['webServer'])`，注册 `/api/ecom-workbench` 前缀。

## 2. 节点说明的写法

### 2.1 帮助页五段（照 Node-RED）

展开节点设置时，详细说明按五段组织：**做什么** / **输入输出** / **何时用** / **注意**。

（原表列了五段，实际落地为上述四段——第五段「示例」对内置节点价值低，暂不做。）

### 2.2 节点级提示分批分级（照 n8n 的 hints 机制）

提示不是「一个字符串」，而是**按条件显示、带级别**的一组。级别决定它的视觉强度。

## 3. 运行时数据在节点上的显示

### 3.1 自己做，不用现成组件

没有合适的现成 npm 组件。结构抄 Langflow（MIT）：**内联在节点卡片里**。

### 3.2 数据走 zustand store，不塞进 React Flow 的 `data`

塞进 `data` 会导致**整个节点重渲染**。

### 3.3 高度封顶 + 只留最近 50 行

不封顶会让节点无限长高，**elkjs 布局会崩**。

### 3.4 两档显示强度

- **活跃态**（queued / running）：展开显示完整日志 + 进度条——用户此刻在看它跑
- **完成态**（success / failed / missing）：**只显示一行摘要**；悬停或选中才展开

**理由**：原来所有终态都展开 108px 日志区，跑完后画布被一堆日志框塞满，而用户真正关心的是「当前在跑什么」。

### 3.5 流式文本自动滚到底

用 `use-stick-to-bottom`（MIT，零依赖）。它的价值在**用户上滑时不抢滚动条**。

## 4. 工程化决定

### 4.1 主题层跟随 dsh，画布内保留自己的

见 [设计计划](../%E8%AE%BE%E8%AE%A1%E8%AE%A1%E5%88%92.md) 第二、三节。

### 4.2 拓扑排序与变量传递

工作流是 DAG。上游输出按端口类型传给下游；多个上游时给数组。

### 4.3 撤销栈记「操作前」的状态

这一条容易搞反（我为此写错过测试）：撤销栈存的是**操作发生之前**的快照，不是之后。

### 4.4 连接规则默认保守

端口未声明 `multi` 时**拒绝多入**；查不到端口定义时**也拒绝**，不因缺信息而放行。

### 4.5 存档名要清洗

工作流名来自界面，**必须清洗路径分隔符与 Windows 非法字符**。不清洗的话 `../` 能写到目录外——这是安全边界，有测试守着。
