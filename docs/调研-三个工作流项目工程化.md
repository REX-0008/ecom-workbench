## 3. 五个重点逐条回答

### 3.1 数据模型与状态管理

- **工作流 JSON 结构（Langflow）**：`types/flow/index.ts:88-99` 是 `NodeDataType`（`type`/`node`/`id`/`showNode`/`output_types`），`:101-106` 是 `EdgeType`+`EdgeDataType`。**节点类型与节点实例分开**：`APIClassType`（`types/api/index.ts:40-60`）是「类型」，`NodeDataType.node` 是「该实例上那份类型快照（含用户改过的值）」。与我们 `model.ts` 的 `NodeDef`/`CanvasNode` 同构。
- **参数 schema**：`types/api/index.ts:90-121` 的 `InputFieldType` —— **一个扁平对象 + 一堆可选开关**（`show`/`advanced`/`list`/`real_time_refresh`/`refresh_button`/`combobox`…），不是判别式联合。**我们要避免这个**：`ParamKind` 判别式更好维护。
- **状态管理**：两者都是 zustand，且都是「一个 store、多 slice」。Langflow 是**多文件独立 store**（`stores/` 下 20 个，按领域分）；Activepieces 是**一个 builder store 内合成 7 个 slice 工厂**（`builder-hooks.ts:54-72`）。**一个画布一个 store 的我们更适合后者。**
- **撤销/重做**：见第 2 节。要点：Langflow 把它放在 **flowsManager** 而不是 flow store（快照跨 flow）；**只快照 nodes+edges、不快照参数**，参数改动靠显式调 `takeSnapshot()`（`use-handle-new-value.ts:125`）。

### 3.2 节点定义与参数表单

- **参数类型体系（两套可对比）**：Langflow = 字符串 type + 开关字段；Activepieces = **TS 枚举 `PropertyType` + 结构化 property 对象**，switch 覆盖 `ARRAY/OBJECT/CHECKBOX/MARKDOWN/RICH_TEXT/STATIC_DROPDOWN/JSON/MULTI_SELECT_DROPDOWN/DROPDOWN/NUMBER/DATE_RANGE/DATE_TIME/SHORT_TEXT/LONG_TEXT/FILE/SECRET_TEXT/DYNAMIC/CUSTOM_AUTH/BASIC_AUTH/OAUTH2/OIDC`（`properties-utils.tsx:56-408`）。**我们 7 种 `ParamKind` 属 AP 派，缺数组/对象/日期类。**
- **表单渲染**：都是「统一 base props + 按类型分发」：Langflow 先判 `TEXT_FIELD_TYPES`（字符串类，`constants/constants.ts:882`）再 switch；Activepieces 一个 `switch (property.type)`。
- **联动显隐**：Langflow 靠**后端回写** `template[field].show`（`use-handle-new-value.ts:131-148` 有乐观隐藏的特例）；Activepieces 靠 **`PropertyType.DYNAMIC` + 动态请求**（`dynamic-piece-property.tsx`）。**两者都不是我们 `showWhen` 那种声明式——我们的更简单，建议保留。**
- **高级折叠**：Langflow 的 `isCanvasVisible` 把 `advanced` 直接排除出画布（`parameter-filtering.ts:30-34`），另用 `process-node-advanced-fields.ts:5-29` 把被连线占用的高级字段提出来；Activepieces 用 `AdvancedSection`（`advanced-section.tsx:31-56`）**且错误时自动展开**。
- **帮助放哪**：字段级 `helper_text`/`info` 挂标签后 ⓘ（`NodeInputField/index.tsx:192-202`）；Activepieces 用 `ReadMoreDescription`（`auto-form-field-wrapper.tsx:108-113`）；节点级 description 见 Langflow `NodeDescription`。

### 3.3 执行与运行状态

- **状态表示**：Langflow 用 `BuildStatus` 枚举（`constants/enums.ts:10`）+ `validationStatus`，状态→样式集中在 `get-class-from-build-status.ts:4-18`，节点通过 `setBorderColor` 回传（`NodeStatus/index.tsx:280-293`）。Activepieces 是 `run.steps[stepName].status` + `loopsIndexes`，节点用 `getStepStatus`（`flow-canvas-utils.ts:638-652`）派生。**我们六态 `NodeState`（`model.ts:11-17`）比两者都细，够用；缺的只是「状态→样式」的集中映射。**
- **日志/输出**：Activepieces 把 `errorLogs`/`consoleLogs` 按 stepName 存进 run slice（`run-state.ts:48-53`），UI 在 `run-details/flow-step-input-output.tsx`（14KB）；Langflow 在出端口挂 `NodeOutputfield` + 弹层。
- **运行历史**：Activepieces **存服务端**（`features/flow-runs/api/flow-runs-api.ts` + `components/runs-table/`，含 `columns.tsx`、`runs-status-chart.tsx`、`failed-step-dialog.tsx`）。**我们是本地插件，要自建存储**；可借的是它的列定义与状态图标（`components/step-status-icon.tsx`）。

### 3.4 画布交互的工程做法

- **连线校验**：Langflow `utils/reactflowUtils.ts:414-540` 是三者中唯一**在拖拽时就判定**的（`handleRenderComponent/index.tsx:295,302` 用它决定 handle 是否可放）。Activepieces **关掉了拖拽连线**（`flow-canvas/index.tsx:237` `nodesConnectable={false}`），新增连线靠图上「+」按钮生成 operation —— 因为它的图是从 `flowVersion` 派生的、不是可自由编辑的图。**我们走 Langflow 路线。**
- **复制/粘贴/框选**：框选 AP 用 React Flow 内建（`selectionMode={SelectionMode.Partial}`，`index.tsx:245`）+ `onSelectionChange`/`onSelectionEnd`（`:78-87`/`:148-181`，**会把 loop/branch 的子节点自动并入选区**，这个细节值得抄）。复制粘贴见第 2 节。
- **自动布局**：Langflow 用 elkjs，配置 `layered`+`RIGHT`+`NETWORK_SIMPLEX`+`LAYER_SWEEP`，**关键是给节点声明 port 并设 `FIXED_ORDER`**（`layoutUtils.ts:70-76`），否则交叉点多；**以及 ELK 失败时的网格兜底**。Activepieces **没有自动布局**（`layout-consts.ts` 全是手排常量）。
- **派生式图（AP 的独特做法）**：`createFlowGraph`（`flow-canvas-utils.ts:694-722`）每次从 `flowVersion`+notes 重算整张图，用 `graphKey`（`:302-327`，把每个 step 的名字/类型/分支/子节点拼成字符串）控制 memo。好处是不存在图与数据不同步；代价是**不能自由拖拽位置——我们可拖拽的画布不适用**。

### 3.5 能抄 vs 不能抄

- **许可上能抄（MIT / MIT Expat）**：第 2 节表内全部 Langflow 项、Activepieces `app/builder/` 下的文件（EE 目录本地不存在，见第 6 节）、litegraph 的那四段算法。下面几条不是许可问题，是**框架绑定**问题——抄了要么编译不过，要么风格与我们的 CSS Module 冲突。
- **不能抄（框架特有）**：
  1. **Tailwind 类名** —— 两家组件样式全是 Tailwind，如 `get-class-from-build-status.ts:12` 返回 `"border-foreground border-[1px] ring-[0.75px] ring-foreground"`。**必须翻译成 CSS Module 类。**
  2. **shadcn/Radix 组件** —— `@/components/ui/*`（Dialog/Popover/Form/Tooltip/Collapsible）。我们的 `NodeEditorPopover` 是用自身实现，这些基元**整块不可用**。
  3. **react-hook-form + zod + TanStack Query** —— AP 表单严格依赖 `FormField`/`useFormContext`/`zodResolver`。我们是受控 props，**`auto-form-field-wrapper` 只能借「字段外壳的分工」而非代码**。
  4. **`@activepieces/shared` 与 `pieces-framework`** —— `PropertyType`、`PieceProperty`、`flowOperations`、`FlowOperationType`、`FlowRun` 全来自**未下载的包**（见第 6 节），只能抄形状。
  5. **Langflow 的 Python 后端** —— `template` 由后端按组件类生成下发（`mutate-template`、`use-post-template-value`）。**「schema 自动生成」这条路我们没有后端、完全不适用**；保留手写 `node-library.ts`。
  6. **i18next / socket.io / react-router** —— AP 的 `t()`、WebSocket 推送、路由全绑死在这三样上。
  7. **litegraph 的整体渲染层** —— canvas 2D 立即模式 + `LGraphCanvas` 鼠标状态机（`processMouseDown:5926`、`processKey:7141`）全部不能用；只取 `:684-712`、`:1150-1300`、`:2185-2240`、`:7232-7300` 四段。
