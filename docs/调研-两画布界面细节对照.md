## 用户 2026-10-29 的定案（逐条落到下面的表）

原话分六组，编号是本文件给的。

### 甲 顶部

1. 两边**都不要顶部栏**；顶部那批功能改成**画布内悬浮**按钮。
2. 两边统一，分左右两侧：**画布名称放左边**，**设置类放右边**。

5. **主操作放底部中间悬浮**（参考的模式）。
6. 内容画布的「加节点」类按钮与执行画布的「运行 / 停止」**是一个级别**，都进主操作位。
   两者逻辑不同但定位相同。
7. 点击切换鼠标模式、撤销重做，**都按参考来**。
8. **设置按钮去右上角**，两边统一。

### 乙 左侧栏

11. 条目**不强行一致**：执行画布有标签，内容画布没有；但都要有**标题 + 说明**，外观近似。

### 丙 右下角浮层

### 丁 顶部浮层（与甲是同一次改动的细节）

### 戊 画布本体

24. **不做空画布引导**。
25. **空格与 Ctrl 都能临时切换左键功能**（两个都认）。

### 己 其他 / 快照

27. 与内容画布一个逻辑：新建、打开这些操作**在工作流管理里做**；画布只专注当前这一份内容。

## 共用一份样式（答用户丁 20）

**能。** 两边设置面板现在各有一套样式：内容画布用 `EcomWorkbench.module.css` 的
`.canvasSettings*`（`:2014-2103`，含 `.canvasSettingsHead` / `Group` / `Label` / `Row` / `Field` /
`Value` / `Check` / `Hint`），执行画布用 `workflow-canvas.module.css` 的 `.drawer*`（`:532-560`）
与 `.scGroup` / `.setRow` / `.setLabel` / `.setRange` / `.setReset` / `.setHint`（`:561-584`）。

统一的做法（不是硬编码，是**共用类**）：

| 一层 | 类名 | 管什么 | 继承自 |
|---|---|---|---|
| 容器 | `.canvasFloatPanel` | 宽 268px、圆角、边框、底色、阴影、`overflow-y` | 现 `.canvasSettingsDrawer` |
| 标题行 | `.canvasFloatHead` | 标题、`flex-1` 撑开、`恢复默认`、`×` | 现 `.canvasSettingsHead` |
| 分组 | `.canvasFloatGroup` | 一组一个标题，组间距 | 现 `.canvasSettingsGroup` |
| 行 | `.canvasFloatRow` | 一行一个设置（左标签右控件 / 左标题下控件） | 现 `.canvasSettingsRow` + `.setRow` |
| 说明 | `.canvasFloatHint` | 只在「看不出后果的开关」下出现，一句简写 | 现 `.canvasSettingsHint` |

**字号与间距取令牌，不写数值**：`--text-ewb-meta` / `--text-ewb-label` / `--text-ewb-caption`
（在 `canvas-tokens.module.css` 定义，已映射到 dsh 语义层），间距用 `gap: 5px` 一档、
组间距 10px 一档，两档足够。**控件本身（滑杆 / 胶囊 / 勾选）各按性质写，不进共用类**——
这正是用户说的「整体样式不是控件样式」。

落点：**加进 `EcomWorkbench.module.css`**（19 个文件已 import，是唯一共用样式文件），
新增一段「画布浮层（票 43）」；`workflow-canvas.module.css` 的 `.drawer*`（`:532-560`）
随执行画布改浮窗一起删掉，`.scGroup` / `.setRow` / `.setLabel` / `.setRange` /
`.setReset` / `.setHint`（`:561-584`）同样处理。

## 必须报的一件事：左侧栏那行「引擎就绪」是假的

用户 2026-10-29 说「引擎连接状态其实在左侧栏有，画布中不需要出现」。
**左侧栏确实有那一行，但它是写死的，不读任何状态。**

```js
// EcomWorkbench.tsx:790
h('span', { className: 'dot ok pulse' }),
navCollapsed ? null : h('span', null, '引擎就绪'),
```

同一份客户端里只有 `WorkflowCanvas.tsx` 读真状态（`:4198`，`engineOk` 三态）。
全仓 `grep '引擎已连接'` 也只有那一处。

所以「把画布那枚删掉」这句话照字面执行，结果是**引擎状态从界面上彻底消失**——
留在左侧栏的那个永远是绿的「引擎就绪」。两条路：

- **甲（推荐）**：把真状态接到左侧栏那一行（三态：连接中 / 已连接 / 未连接），画布里删掉。
  一行小字，符合「简约点」。代价：`EcomWorkbench.tsx` 要多一个探测（复用 `dispatch-client.ts:272` 那个探测）。
- **乙**：左侧栏那行照旧当装饰、改个说法（比如去掉「引擎」二字，只留一个状态点），
  画布里那枚保留。
