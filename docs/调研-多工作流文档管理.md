## 一、五个问题 × 三个项目（速览）

| 问题 | ProductFlow | TradeMind | FounderOS |
| --- | --- | --- | --- |
| 多个工作流同时打开 | **不存在**；一个商品一个页面 | **不存在**；6 个独立路由页 | **不存在**；网格 + 一次只展开一个 |
| 当前工作流名 | 顶部面包屑显示**商品名**，不显示工作流名 | 列表页标题 / 弹窗标题 | 卡片标题 `wf.name` |
| 「未保存」标记 | 只有**节点级**徽标，无整份文档标记 | 无 | 无 |
| 新建 / 关闭入口 | 新建：加节点面板；无关闭 | 新建：弹窗；关闭：取消 | 新建：列表头部右侧主按钮；关闭：卡片右上 X |
| 标签页 vs 列表 | 列表与画布是**两个独立路由** | 页面 = 左侧菜单项 | 列表 = 同一页的网格 |

## 二、三个项目各自怎么做

### 2.1 ProductFlow（React + React Flow，工作台主要参考）

**没有标签页。** 路由驱动，一个商品一个页面：`web/src/App.tsx:68-99` 的 `<Routes>`，`/products/:productId` → `ProductDetailPage`。
全项目搜 `Tab` 只命中 6 个文件，**全是「页内视图切换」**（侧栏分区、设置页子页签），没有一处是「多文档打开」；`activeTab` 0 命中。

**工作流怎么组织**：一个商品保留多个历史版本，但**只有一个是当前的**。
`backend/src/.../infrastructure/db/models.py:167-179`：`ProductWorkflow`，注释「一个商品可以保留多个历史 DAG，当前使用 active=True 的工作流」，并有唯一索引 `uq_product_workflows_one_active_per_product`。
前端按商品取当前工作流：`web/src/lib/api.ts:306` `/api/products/${productId}/workflow`。后端懒创建：`presentation/routes/product_workflows.py:55` `get_or_create_product_workflow`。

**当前名显示在哪**：`ProductDetailPage.tsx:2032` `<TopNav breadcrumbs={product.name} />` → `TopNav.tsx:167-172` 渲染成 `ProductFlow / 商品名`。
即**显示商品名，不显示工作流名**。工作流自己有 `title` 字段（`lib/types.ts:302`），但**界面上没渲染**（搜 `workflow.title` 无界面命中）。

**未保存标记**：只有节点级的保存状态胶囊 —— `product-detail/InspectorPanel.tsx:196-208`，四种文案在 `lib/i18n.ts:665-668`：`自动保存 / 保存中 / 已保存 / 保存失败`。
整份文档级没有：`dirty` 0 命中、`isDirty` 0、`beforeunload` 0。
它用另一套办法绕开「未保存」：**运行前先自动保存**，说明见 `pages/HelpPage.tsx:266-267`「工作流运行读取的是已保存内容…运行按钮会先尝试保存；如果保存失败，运行不会继续提交」，以及 `HelpPage.tsx:346`「如果当前节点有未保存草稿，切换选择前页面会先尝试保存」。

**新建 / 关闭入口**：工作流没有「新建一份」「关闭一份」的按钮。入口是**加节点**：`ProductDetailPage.tsx:1826-1873` `renderSingleNodePanel`（卡片 + `+` 按钮，文案 `detail.addNode`，`i18n.ts:453`）。工作流本体由后端在首次访问时创建。

**空状态**：两份都做成了正经设计——
- 商品列表空态 `ProductListPage.tsx:319-331`：虚线框 + 图标 + 标题 + 说明 + 主按钮「新建」；
- 图片会话列表空态 `image-chat/ImageChatSessionList.tsx:70-74`：虚线框内一句话。

**「列表 ↔ 当前项」在哪看**：在**图片会话**里（不是工作流），形态是**左侧栏列表 + 右侧内容**：
`ImageChatPage.tsx:988-1030` 左侧 `<aside>`，宽度可拖（第 992-1000 行的拖拽把手），头部是「会话 + 数量」+ 右侧一个 `+` 圆钮（1007-1015）。
选中态：`ImageChatSessionList.tsx:100-106` 高亮边框 + ring；卡片内容 = 缩略图 + 标题 + 轮数 + 时间（119-142）。
移动端同一份列表搬进抽屉：`ImageChatPage.tsx:1380-1424`。
**列表页和画布是两个独立路由**，靠跳转互达，不是标签页、也不是同一页的侧栏。

### 2.2 TradeMind（Go + React/AntD）

**结论：它没有「工作流编辑器」，也就没有「多个已打开的工作流」。**

- 管理端是 Ant Design Pro，**没有画布依赖**：`admin/package.json:13-28` 只有 antd / pro-components / umi；搜 `reactflow`、`react-flow`、`@xyflow`、`antv/x6`、`logicflow`、`jsplumb`、`dagre` **全 0 命中**；搜 `Workflow`（大写）**0 命中**。
- 该项目里语义上的「工作流」是 **ComfyUI 的 workflow JSON 文本**，是一个配置字段：`admin/src/constants/imageProviders.ts:278` `label: 'ComfyUI 工作流 JSON'`、`pages/Settings/Image/index.tsx:165`。不是可编辑的文档。

**「采集中心」的实际形态：一组各自独立的页面。**
路由 `admin/config/routes.ts:274-315`：`/collect` 下 6 个兄弟页 —— 采集中心(Hub) / 采集任务 / 批量采集 / 浏览器登录状态 / 采集规则 / 采集监控。左侧菜单展开成这些项，点一个换一页。
Hub 是**导航首页，不是画布**：`pages/Collect/Hub/index.tsx:516-590` 用 `SectionCard` 分区（采集来源 / 登录与验证风险 / 浏览器登录状态 / 失败恢复），卡片里是「去处理」按钮做跳转（如第 437 行 `history.push('/collect/tasks')`）。

**编辑一份规则的入口是弹窗，不是标签页**：`pages/Collect/Rules/index.tsx:242-417` `ModalForm`，标题按 `editingId` 在「编辑采集规则 / 手动新建采集规则」之间切（251-252 行）；删除是 `Popconfirm`。
**详情用抽屉**：`pages/AI/OperationWorkbench/index.tsx:305-337`，且把「打开了哪一条」写进 URL 查询参数（第 143 行 `useUrlDrawerState('todo')`），刷新后还能回到同一条。

**全局 54 处 `Tabs`，全是「同一页内切换视图/分组」**，例如 `pages/Product/DraftDetail/index.tsx:2609`、`pages/Settings/Platforms/index.tsx:730`，**没有一处是「多文档打开」**。

### 2.3 FounderOS（Next.js）

`/workflows` 是**单页**（`app/workflows/page.tsx`，184 行），没有多工作流标签。

**组织形态：网格 + 原地展开，一次只展开一个。**
`components/WorkflowTree.tsx:136-157` 是 3 列网格；`expandedId` 是**单值** `useState<string | null>`（第 81 行），第 138 行 `const expanded = expandedId === wf.id`。
收起靠右上角 `X`（`WorkflowTree.tsx:267-278`），或点卡片外任意位置（第 112-118 行，**捕获阶段**监听 `click`，注释解释了为什么不能等到冒泡/reflow）。

**当前名**：卡片标题 `wf.name`（第 251 行，`text-[15px] font-medium truncate`）+ 下一行 `trigger: ...`（第 252 行）。展开后右上角是 `X`；未展开时右上角有一个铅笔（编辑），平时透明、悬停才出现（255-266 行）。

**新建 / 关闭入口**：
- 新建 = **列表头部右侧的主按钮**：`WorkflowTree.tsx:131-133` `<Plus/> New workflow`；

**标签机制**：`SlidingTabs` 是**固定宽度 + 滑动指示器**（`components/SlidingTabs.tsx:18-32`，宽度用 `gridTemplateColumns: repeat(n, tabWidth px)`，指示器靠 `translateX(i * tabWidth)`），被三处当**视图切换**用：`AgentsTabs.tsx:110`、`CommsTabs.tsx:46`、`BrainGraphView.tsx:51`。**不是文档标签。**

**唯一像「多文档标签」的地方是 blueprint 的右侧面板**（值得单独看）：
- 状态是「最近打开」栈：`components/blueprint/HierarchyWorkspace.tsx:36` `const [opened, setOpened] = useState<string[]>([])`；

这是**同页内的最近项栈**，不是文件级多文档：没有「新建标签」，也没有未保存标记。

## 三、共性规律

1. **三个项目都没有「浏览器式多文档标签」。** 没有新建标签按钮、没有关闭标签、没有标签上的未保存圆点。`closeTab` 全仓库只出现在 FounderOS 的 blueprint 面板一处。
2. 「多个」这件事都落在**一个列表 + 一个详情**：ProductFlow 用两个路由（列表页 ↔ 商品页），TradeMind 用分组路由 + 抽屉/弹窗，FounderOS 用网格 + 原地展开。**没有一家把多份文档并排成标签。**
3. 当前项的标识靠**标题文字 + 选中态高亮**，不靠标签栏。ProductFlow 用面包屑（商品名），FounderOS 用卡片标题。
4. 保存状态只做在**更小的粒度**上：ProductFlow 是节点级徽标（`InspectorPanel.tsx:196-208`）；**三家都没有「这份文档整体未保存」的标记**。离开前拦截只有 TradeMind 的发布向导草稿一处（`useWizardDraft.ts:58-66`），与工作流文档无关。
5. **新建入口的通用位置是「列表区域的头部右侧」**（FounderOS `WorkflowTree.tsx:131` 的 `+ New workflow`；ProductFlow `ImageChatPage.tsx:1007-1015` 会话列表头部的 `+` 圆钮）。**关闭入口是「卡片 / 面板自己右上角的 X」。**
6. **空状态被当成正经设计**：一句话说明 + 一个引导动作（ProductFlow `ProductListPage.tsx:319-331`、`ImageChatSessionList.tsx:70-74`；我们自己的 `WorkflowList.tsx:197-212` 已经这么做）。FounderOS 的 workflows 页是唯一例外。

## 四、对我们（dsh 插件 + React Flow）的可行性判断

**现在是什么**：`EcomWorkbench.tsx:367-375` 的 SlidingTabs 是**板块内的视图切换**（画布 / 工作流 / 运行历史），不是文档标签；打开一份工作流走的是跨 tab 的模块级交接（`pending-load.ts` 的 `requestOpen` / `takePending`）；画布工具栏（`WorkflowCanvas.tsx:1288-1360`）已有 保存 / 打开 / 快照 / 恢复 / 导入。**没有当前文档名，也没有未保存标记。**

**建议：保持「列表 + 单画布」，先补「当前文档名 + 未保存点」，不要做标签页。** 三条理由：
1. 三个参考项目**没有一家做多文档标签**，没有可抄的先例，自创成本高；
2. 我们的画布嵌在对话列里、宽度有钳制还能拖着改（`EcomWorkbench.tsx:20-28`、141-165），横向空间本来就紧，标签条要再吃掉一行——而「快速切回某份」的价值已经由「工作流」tab 的列表承担了；
3. React Flow 一份画布一套实例与撤销栈，多标签要同时保活多个实例（内存 + 各自历史），收益不成比例。

**具体补法（按改动从小到大）**：
1. 工具栏最左的 `工作流画布` 字样（`WorkflowCanvas.tsx:1289`）换成「当前文档名 + 未保存点」。名字现成：`applyWorkflow(doc, from)`（1164 行）已经在收 `from`（如 `'打开 xxx'`），把它存成 state 即可。
2. 未保存点 = 比对「当前画布快照」与「最后一次保存时的快照」；`WorkflowCanvas.tsx:838` 已有当前快照、`history-store.ts` 已有撤销栈。
3. 先修「切 tab 再切回来就没了」：现在 `EcomWorkbench.tsx:377-392` 按 tab 条件渲染，画布一卸载状态即丢。这是「多份同时开着」体验里最常被指出的那一步，成本也最低。

**如果将来确实要同时开两三份**：形态选 **FounderOS 的「网格 + 原地展开」**（`WorkflowTree.tsx`），比标签页省横向空间，而且我们的视觉语言已经在照抄它。标签页放在最后考虑。
