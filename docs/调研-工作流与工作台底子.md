# 工作流与工作台底子调研（第二轮·可借用性深挖）（2026-10-05）

> 状态：已完成 · 日期：2026-10-05 · 编号：95 · 层：调研
> 原则：不重复造轮子。每条结论回答「能不能直接用 / 抄哪一部分」。
> 实测方式：宿主 pwsh 调 GitHub API + raw.githubusercontent（star/许可均为实测值，非印象）。

## 一、一句话结论

| 方向 | 首选 | 能否直接借用 |
|---|---|---|
| ① 可视化工作流界面 | **dsh-node-flow**（现成 dsh 插件）+ **React Flow** 打底 | **能直接用**。dsh-node-flow 已实现拖拽加节点/连线/属性面板，且是 dsh 插件；视觉与交互细节抄 **ProductFlow** 的画布层 |
| ② 生图工作流 | **@comfyorg/sdk**（官方 TS SDK，MIT）只调 API + 自己画界面 | **能直接用 SDK**；界面结构抄 **HEISS-UI**（MIT，React19+TS，正是「不要图、只要提示词+画廊」的形态） |
| ③ 工作台底子 | **dock**（AKS1st，现成 dsh 插件，VSCode 风格外壳 + 面板注册表） | **能直接用**。多入口/多面板/可停靠/布局持久化全都有，功能面板按需挂 |

**结论：三个方向都有能直接拿来用的东西，不需要从零写。** 三个首选全部是 MIT，且②③的载体天然就是 dsh 插件。

## 二、第一节：可视化工作流界面

### 1. React Flow（xyflow）— 打底库，直接用
- 地址：https://github.com/xyflow/xyflow ｜ **38586★** ｜ MIT ｜ TypeScript
- 包：`@xyflow/react` v12.12.0（npm 实测 2026-09-24 更新）｜ peer: react >=17
- **能不能直接用：能。** `npm i @xyflow/react` 即可嵌入任意 React 应用，无需后端。
- **可借用**：整个画布能力——拖拽节点、拉线连接、缩放平移、多选框选、MiniMap、Controls、自定义节点/边类型。这是本方向唯一需要的基础设施。
- **缺点**：只给「画布」，不给「节点面板 / 属性面板 / 工作流 JSON 模型 / 运行态」，这些要自己写（或用下面两个项目现成的）。
- 备选（均 MIT，均不如它）：`reactflow` v11（2024-06 停更）、`drawflow`、`litegraph.js`（Canvas 实现非 React 组件）。**不建议换。**

### 2. dsh-node-flow — 首选，现成 dsh 插件 ⭐
- 地址：https://github.com/CodermanYHZ/dsh-node-flow ｜ **9★** ｜ MIT ｜ TypeScript
- 技术栈：React Flow 12 + Zustand + Vite ｜ 依赖 `@xyflow/react ^12.3.0`、`zustand ^4.5.5` ｜ peer: `@deepseek-ai/cordis ^4.0.1`、react 18
- **能不能直接用：能，且是 dsh 插件。** `dsh plugin --profile web add git+https://github.com/CodermanYHZ/dsh-node-flow.git`，重启 Web UI 后侧边栏出现「节点模式」。
- **它已经有什么**（源码实测）：`src/components/Canvas.tsx`(147 行，React Flow 封装 + 拖拽落点 `screenToFlowPosition` + Delete 键删边/删点)、`NodePalette.tsx`（左侧节点面板，拖拽新增）、`Inspector.tsx`（右侧属性面板）、`Toolbar.tsx`、`ScheduleBoard.tsx`（Cron 定时）、`CodeEditorModal.tsx`、`store/canvas.ts`(144 行 Zustand)。
- **可借用**：**整套**。`store/canvas.ts` 注释明确写「kept framework-agnostic so the same store can back both the standalone demo UI and the embedded DSH client plugin」——画布层与 dsh 宿主解耦，`npm run dev` 可独立 Vite 预览。改成电商节点只需改 `src/model.ts` 节点类型表与 `nodes/WorkflowNodeView.tsx` 渲染。
- **明显缺点**：**star 仅 9，2026-08-28 后未更新**；「运行引擎」部分（Agent/Code/If/Loop）**用不上**，需按电商重写节点类型——但正好符合「不需要强大执行引擎」。

### 3. ProductFlow — 视觉与交互的抄写来源 ⭐（委托人点名）
- 地址：https://github.com/yuqie6/ProductFlow ｜ **305★** ｜ MIT ｜ 前端 React 19 + Vite + TypeScript
- 前端栈实测：`@xyflow/react ^12.10.2`、react 19.1、react-router-dom 7、@tanstack/react-query 5、tailwindcss 4、vaul、lucide-react
- **能不能直接用：前端可以，后端不能。** 它的后端是 Python（FastAPI + PostgreSQL + Redis + Dramatiq worker），与「TS 统一前后端」冲突。**前端 MIT，可整体移植。**
- **可借用的具体部分**（`web/src/pages/product-detail/`，全部实测存在）：
  - `WorkflowCanvas.tsx`（**1363 行**，最核心：缩放/平移/节点拖拽/连线/边删除/Ctrl·Cmd·Shift 多选/Shift 框选/触摸手势/运行态光效）
  - `WorkflowNodeCard.tsx`（205 行，节点卡片视觉：248px 宽、圆角、毛玻璃、状态胶囊、图片预览、选中环、`animate-running-glow` 等动画）
  - `reactFlowAdapters.ts`（150 行，**业务模型 ⇄ React Flow 的纯函数转换**，零依赖，最值得直接抄）
  - `workflowConfig.ts`、`workflowHistory.ts`（撤销）、`selection.ts`、`shortcuts.ts`、`constants.ts`、`types.ts`
  - 大量配套测试（`*.test.ts`），移植时是回归保障
- **明显缺点**：①画布层与它自己的 `lib/api.ts` + `ProductDetail` 数据结构耦合，需替换数据层；②它是**单管理员私有实例**（README 明说「暂不提供多用户/多租户」）；③后端 Python，若要其完整能力等于引入第二语言栈。
- 在线体验：https://draw.devbin.de

### 4. 视觉参考（只看不做）
- FounderOS `/funnel`、`/blueprint`（见第三节）；HEISS-UI 瀑布流画廊 + 悬浮提示词条（见第二节）。

## 三、第二节：生图工作流

### 1. ComfyUI 的许可与嵌入真相 ⚠️
- 主仓 https://github.com/Comfy-Org/ComfyUI ｜ 136198★ ｜ **GPL-3.0**；官方前端 https://github.com/Comfy-Org/ComfyUI_frontend ｜ 2052★ ｜ **GPL-3.0**。
- **关键判断**：本体与官方前端都是 GPL-3.0，抄其代码有传染风险；**「通过 HTTP API 调用它」属正常使用，不构成派生作品** —— 正解是**只调 API、自己画界面**，不要 fork 它的前端。
- README 实测确认提供：「Reusable subgraphs, workflow templates, **App Mode**, and a **local API**」，即 API 模式是官方支持路径。
- **有没有现成 React 组件能嵌 ComfyUI？** 未找到官方组件，社区做法是 iframe 或调 API。**结论：走 API。**

### 2. @comfyorg/sdk — 首选，直接用 ⭐
- 地址：https://github.com/Comfy-Org/comfy-typescript-sdk ｜ 12★ ｜ **MIT** ｜ TypeScript
- npm：`@comfyorg/sdk` v0.4.0（2026-10-02 更新）｜ 「TypeScript SDK for running ComfyUI workflows via the Comfy API v2 (self-hosted, Comfy Cloud, serverless)」
- **能不能直接用：能。** 官方维护、MIT、TS，与我们技术栈完全一致。**这是「只调 API、自己画界面」的最省事路径。**
- 备选：`@saintno/comfyui-sdk` v0.3.1（266★，MIT，https://github.com/comfy-addons/comfyui-sdk），但 2026-04 后未更新，次选。
- **可借用**：工作流提交、队列、进度、结果取回的全部协议。界面 100% 自己画。

### 3. HEISS-UI — 界面形态直接抄 ⭐
- 地址：https://github.com/tristmeister/HEISS-UI ｜ 34★ ｜ **MIT** ｜ React 19 + TypeScript + Vite
- 栈实测：Tailwind 4、Radix UI、framer-motion、lucide-react、sharp、express（devDependencies 里）
- **定位原话**：「ComfyUI, without the graph.」——**「不要节点图，只要提示词框 + 画廊 + 该模型的关键设置」**，正是要的形态。
- **能不能直接用：能借鉴整套前端形态。** 它「Bring your own workflow」：导入 ComfyUI 工作流（API 或可视化 JSON）后，自动变成一组控件，图在底下跑。
- **可借用**：瀑布流画廊（先像素马赛克再变清晰）、悬浮提示词条、按模型收敛的参数面板、LoRA 堆叠、对比滑块、Zen 全屏、最近提示词（↑）、手机端单拇指布局。
- **明显缺点**：是**完整应用**不是组件库，需按需摘取；用 express 做本地服务，与 dsh 宿主重叠需裁剪。在线体验：https://heiss-ui.vercel.app/

### 4. 素材库 / 批量生图（现成 dsh 插件，可直接装）
- **dickpy/dsh-imagegen** ｜ https://github.com/dickpy/dsh-imagegen ｜ **99★** ｜ Apache-2.0 ｜ TS ｜ 2026-09-30 更新
  - 经可配置的 OpenAI 兼容端点做文生图/图生图。**可直接装**——兼容端点意味着即梦/可灵/SD 网关都能接。
- **fandc520/dsh-comfyui** ｜ https://github.com/fandc520/dsh-comfyui ｜ **97★** ｜ MIT ｜ TS
  - 提供 `comfyui_run` / `comfyui_object_info` / `comfyui_workflow` 三个 agent 工具驱动 ComfyUI。**可直接装**，是调 ComfyUI 的现成工具层。
- **素材库**：yuanyiHY/deepseek-media-gallery（0★，MIT）侧边栏弹窗浏览/预览/下载/删除生成图。**功能对但 0★，只参考不依赖。**
- **不推荐**：weshopai/weshop-dsh-plugin（13★，MIT）形态接近，但**强绑 WeShop 自家 API 与商业 Key**。

## 四、第三节：工作台底子（多入口外壳）

### 1. dock — 首选，现成 dsh 插件 ⭐⭐（本项优先级最高，已找到）
- 地址：https://github.com/AKS1st/dock ｜ **9★** ｜ MIT ｜ TypeScript
- npm：`dock-base` v0.2.4 ｜ 要求 dsh >= 0.1.3-alpha.2、cordis ^4、react 18（peer 可选）
- **能不能直接用：能，它就是 dsh 插件。** `dsh plugin --profile web add dock-base`
- **它提供什么**（README 实测）：**VSCode 风格布局外壳**（活动栏 / 侧边栏 / 编辑器区 / 面板 / 状态栏）+ **开放注册表服务 `ctx.workbench`**。
  - 注册 API：`registerActivityBarItem` / `registerPanel` / `registerEditorView` / `registerStatusBarItem` / `registerCommand` / `registerSetting`，**全部返回反注册函数**，配合 `ctx.effect` 随插件停用自动清理。
  - 布局持久化到 localStorage；可停靠屏幕四边；支持独立浮窗（可拖动/缩放）。
- **可借用**：**整个外壳**。我们的「多入口」= 往活动栏注册图标项；每个业务板块 = 往面板/编辑器区注册一个视图。**这正是委托人认可的「一个板块一个目录」的工程化版本。**
- **配套插件（按需装）**：dock-files（5★，文件树）、dock-editor、dock-images、dock-markdown、dock-git。
- **明显缺点**：**9★、v0.2.4、非常新**；要求 react 18（上 React 19 需验证 peer）；**未实际安装运行**（见未获取清单）。

### 2. DSH-better-sidebar — 强信号备选
- 地址：https://github.com/omdsh-dev/DSH-better-sidebar ｜ **4006★** ｜ MIT ｜ TypeScript ｜ 2026-10-05 更新
- 「Full sidebar workbench with file rendering and editing, terminal, Git, and subagents; **third-party plugins can register new tabs**」
- **能不能直接用：能装。** 「第三方可注册新 tab」等于提供面板挂载点。**star 量级远高于 dock，是更稳的宿主选择**；代价是它偏「文件/终端 IDE」，多入口气质不如 dock 纯。

### 3. FounderOS — 只抄结构，不能直接用
- 地址：https://github.com/Bennettxai/FounderOS-DEMO ｜ **978★** ｜ MIT ｜ TypeScript ｜ Next.js
- **能不能直接用：不能。** 实测其外壳强绑 Next.js App Router：`app/layout.tsx`(71 行) 是 **server component**（内部调 `getDb()` 取数）、`components/Sidebar.tsx`(247 行) 用 `next/link` + `usePathname`、页面按 `app/<板块>/page.tsx` 目录路由（20+ 个板块）。而 **dsh 插件是客户端 React 组件**，两套路由/渲染模型不兼容，硬搬等于引入 Next.js 运行时。
- **可借用的具体部分**：
  - `lib/nav.ts` 的**导航分组结构**（`NAV_OPERATE` / `NAV_AGENTS` / `NAV_INTELLIGENCE` / `NAV_SYSTEM` / `NAV_LIBRARY`）——「一个板块一个目录」的清单化写法，可直接照搬为我们的入口表。
  - 侧边栏**折叠 + 拖拽调宽**实现（`COLLAPSED_W=56`、`MIN_W=190`、`MAX_W=420`、`DEFAULT_W=232`，含折叠态用 fixed 定位做 tooltip 的坑位注释）。
  - **布局用 CSS 变量让位**：`marginLeft: var(--sidebar-w)` / `marginRight: var(--conductor-w)`——面板展开时内容列滑走而非被遮挡，这个模式很值得抄。
  - 主题防闪：`THEME_INIT_SCRIPT` 在首次绘制前注入。
- **明显缺点**：Next.js 服务端组件 + SQLite 仓储层（`lib/db.ts` 20+ 仓储、`lib/connectors/*` 20+ 连接器）体量巨大，**绝大部分与「工作台底子」无关**，是它自己的业务。**只抄上面 4 点，不要整体搬。**

### 4. 原生路径（兜底）
dsh 自带 typed React 组合系统 `ctx.slots.inject(key, () => ctx.slots.register({...}))`，已有 `sidebar.panellist`、`main`、`shell.overlay`、`sidebar.right.pane.tab` 等孔位；本工作区 `my-dsh-plugins/workbench` 已在用。**不装 dock 也能用官方 slots 自拼外壳，只是要自己写布局骨架。**

## 五、借用清单总表

| 你要的功能 | 借用谁 | 借用方式 | 工作量估计 |
|---|---|---|---|
| 节点画布底子（拖拽/连线/缩放） | React Flow `@xyflow/react` | **直接用**（npm 依赖） | 0.5 天（接入 + 样式） |
| 可编排工作流界面（含节点面板+属性面板） | dsh-node-flow | **直接装**，改 `model.ts` 节点类型与节点渲染 | 1–2 天（含改造） |
| 画布交互细节 / 节点卡片视觉 | ProductFlow `web/src/pages/product-detail/` | **抄代码**：`reactFlowAdapters.ts` 先抄，再摘 `WorkflowNodeCard.tsx`、`selection/shortcuts/workflowHistory` | 2–3 天 |
| 生图 API 调用层 | `@comfyorg/sdk` | **直接用**（npm 依赖，MIT） | 0.5 天 |
| 生图界面形态（提示词框+画廊+参数） | HEISS-UI | **抄结构**（MIT），摘瀑布流画廊与设置面板 | 2 天 |
| ComfyUI 工具接入（dsh 内） | fandc520/dsh-comfyui（97★ MIT） | **直接装** | 0.5 天 |
| 通用生图（OpenAI 兼容端点） | dickpy/dsh-imagegen（99★ Apache-2.0） | **直接装** | 0.5 天 |
| 多入口工作台外壳 | **dock**（`dock-base`） | **直接装**，用 `ctx.workbench` 注册各板块面板 | 1 天（+ 每板块 0.5 天） |
| 工作台外壳备选宿主 | DSH-better-sidebar（4006★） | **直接装**（用其第三方 tab 注册） | 1 天 |
| 导航分组 / 侧边栏折叠 / 布局让位 | FounderOS | **仅参考**（抄 nav 分组写法与 CSS 变量布局思路） | 0.5 天 |
| 素材库 | 暂无合格现成件 | 自建（可参考 deepseek-media-gallery 交互） | 2–3 天 |

**最短路径**：dock（外壳）+ dsh-node-flow（画布）+ @comfyorg/sdk（生图）+ 抄 ProductFlow 的 adapters/节点卡片（视觉）→ **三方向底子齐活，预计 1 周内可跑通骨架。**
