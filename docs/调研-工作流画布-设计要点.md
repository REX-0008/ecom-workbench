## 零、最值得采用的 3 条

1. **节点状态用「包装器 + 变体」而不是往节点里塞 if**：React Flow 官方 UI 库把状态抽成 `NodeStatusIndicator`，status ∈ `success/loading/error/initial`，loading 还分 `border`（转圈描边）与 `overlay`（整块蒙层 + spinner）两种变体。我们照这个 API 形状抄，节点组件本身不用知道状态怎么画。
2. **端口类型靠「颜色 + 形状 + 连线同色」三重编码**：ComfyUI 明说「只能连同色的」，端口色 = 连线色 = 数据类型色；Blender 更进一步用**形状**区分数据结构（圆=动态、矩形=单值、菱形=field、网格、三横线=list）。颜色防误连、形状防误读。
3. **自动布局不要自己写**：dagre 内部有 `acyclic.ts`——先跑一遍**反馈弧集**（greedy 或 DFS）把环上的边**删掉、反向重加**并标记 `reversed`，布局完再 `undo` 还原。**它对有环图天然安全**，正好治 ProductFlow 那个死循环。

## 一、React Flow 官方：节点与画布

**节点本体**
- 官方明确「**建议自己做自定义节点**而不是用内置节点」，因为自定义节点能塞任意内容（表单、图表、交互元素）。自定义节点就是一个普通 React 组件，`<ReactFlow>` 自动包一层容器注入 id/position/data 与选中、拖拽、连线能力。（https://reactflow.dev/learn/customization/custom-nodes ）
- 官方 UI 库给出的**节点信息骨架**（`BaseNode`）：`BaseNodeHeader` + `BaseNodeHeaderTitle`（放标题与操作）/ `BaseNodeContent`（主体）/ `BaseNodeFooter`（补充信息或可见操作）。**这直接回答「一个节点上显示什么」**。（https://reactflow.dev/ui/components/base-node ）
- 节点里放按钮/滑块等交互元素，**必须加 `nodrag` 工具类**，否则点按钮会变成拖节点。（同上）
- 还有 `NodeAppendix`：在节点上**绝对定位**挂动态附加信息（徽标、可交互块），不占主体布局。（https://reactflow.dev/ui/components/node-appendix ）

**端口（Handle）怎么不容易连错**
- 一个节点有多个同类端口时，**每个必须给唯一 `id`**，边用 `sourceHandle`/`targetHandle` 指向它。（https://reactflow.dev/learn/customization/handles ）
- 默认端口在所在边的**正中**；同一边要放多个，得自己用内联样式/CSS 调位置。**注意**：要隐藏端口必须用 `visibility: hidden` 或 `opacity: 0`，**不能用 `display: none`**——RF 要量端口尺寸，`display:none` 会报 0 尺寸。（同上）
- 连线过程中，端口会拿到 **`connecting`**（连接线悬停其上）与 **`valid`**（该连接合法）两个 class——**「合法/非法/悬停」三种反馈是框架给的，不用自己算**。（同上）
- 想不区分输入输出，设 `connectionMode="Loose"`；端口数量/位置会变，调 `useUpdateNodeInternals`。（同上）
- 官方还给了 `LabeledHandle`（带文字标签的端口）与 `ButtonHandle`。（https://reactflow.dev/ui/components/labeled-handle ）

**画布操作**
- 默认操作是「滑地图」式：拖拽平移、滚轮缩放、Shift+拖拽框选。想变 **Figma/设计工具**式：`panOnScroll` 与 `selectionOnDrag` 设 true、`panOnDrag` 设 false，并把 `selectionMode` 设 `partial`（部分选中即算选中）。（https://reactflow.dev/learn/concepts/the-viewport ）
- 内置组件四件套：`MiniMap`（鸟瞰，可传 `nodeColor` 函数按状态上色）、`Controls`（缩放/适配）、`Background`（网格底，帮用户保持方位感）、`Panel`（固定不动的浮层）。（https://reactflow.dev/learn/concepts/built-in-components ）
- 无障碍是**框架内置**的：Tab 遍历节点与边、Enter/Space 选中、方向键移动节点（Shift 加速）、聚焦自动平移到该节点；文案可用 `ariaLabelConfig` 本地化（含中文）。（https://reactflow.dev/learn/advanced-use/accessibility ）

**大图性能（官方给的顺序）**
1. 节点/边组件用 `memo` 或声明在父组件外；传给 `<ReactFlow>` 的函数用 `useCallback`，数组/对象用 `useMemo`。
2. **不要在组件里直接读整个 `nodes` 数组**——拖拽时它每次都变；把「选中 id 列表」这类派生状态单独存（Zustand/Redux）。
3. **折叠大树**：用节点的 `hidden` 属性动态隐藏子节点，只渲染展开的部分。
4. 最后才简化节点样式——**动画、阴影、渐变最吃性能**。（https://reactflow.dev/learn/advanced-use/performance ）

## 二、社区范式（非 React Flow）

**ComfyUI —— 状态与连线的教科书**
- 节点状态：**Normal / Running / Error / Missing**。Missing 专门区分「核心节点缺失（版本旧）」与「自定义节点未安装」——**这类「环境缺件」状态我们做「节点必须声明依赖」时正好需要**。（https://docs.comfy.org/basic-concepts/nodes ）
- **端口色 = 连线色 = 数据类型色，且只能连同色**。它的类型色表是现成的（扩散模型薰衣草、CLIP 黄、VAE 玫瑰、conditioning 橙、latent 粉、图像蓝、mask 绿、数值灰/浅绿、mesh 亮绿）。（https://docs.comfy.org/basic-concepts/links ）
- 连线渲染模式可切：**Straight / Linear / Spline / Hidden，默认 Spline**；并可「一键隐藏所有连线」——**学习/分享/调试时显示，定稿后隐藏以降噪**。（同上；默认值见 https://docs.comfy.org/interface/settings/lite-graph ）
- 连线太长太乱时用 **Reroute 节点**手工引线；中键可直接新建 Reroute。（同上）
- 值得抄的画布开关：**「拖线悬停到节点时高亮该节点」**、**「自动吸附到最近的可用插槽」**、**「删除中间节点时自动重连上下游（bypass）」**、**「低质量渲染缩放阈值 0.6」**（缩到 0.6 以下切低清）、组内边距 10、tooltip 延迟 500ms。（https://docs.comfy.org/interface/settings/lite-graph ）
- 节点徽标（badge）可显示 **节点 ID / 来源（核心 or 哪个自定义包）**——「这节点哪来的」在插件生态里是刚需。（https://docs.comfy.org/basic-concepts/nodes ）
- 快捷键已高度标准化：`Alt+C` 折叠、`Ctrl+M` 静音、`Ctrl+B` 旁路、`Ctrl+G` 加框、`. ` 适配选中、`Ctrl+Z/Y` 撤销重做、空格临时平移。（https://docs.comfy.org/interface/shortcuts ）
- **子流程（Subgraph）＝ 把一组节点打包成一个可复用节点**，官方叫「工作流的文件夹」，双击空白处进入编辑。（https://docs.comfy.org/interface/features/subgraph ）
- 值得一提的架构演进：ComfyUI 把节点渲染**从 Canvas（LiteGraph.js）换成了 Vue 的 DOM 渲染**，理由正是「Canvas 上做交互增强和可展开节点太慢」。**这反向支持我们选 React Flow（DOM 渲染）是对的**。（https://docs.comfy.org/interface/nodes-2 ）

**n8n —— 运行时与运维语义最全**
- 节点悬停才出现的控件：**执行本步 / 停用 / 删除**；右键菜单含 打开、执行、重命名、停用、**Pin**、复制、**Tidy up workflow（自动整理）**、**转成子工作流**。（https://docs.n8n.io/build/understand-workflows/workflow-components/work-with-nodes ）
- 节点设置里直接暴露**失败语义**：`Retry On Fail`（失败自动重跑）、`On Error` 三选一 —— **Stop Workflow / Continue（用上一份有效数据）/ Continue (using error output)（把错误当数据传给下游）**。**这个「错误可作为数据继续流」的设计，值得直接进我们的派发器语义。**（同上）
- 节点备注（Note）可勾选**「在流程中显示」→ 变成节点副标题**。（同上）
- **Canvas Groups**（画布分组）：框选后 `Ctrl+G` 成组、可命名、可加**≤145 字描述**、可折叠成只剩标题。细节很讲究：描述在**缩放到约 2/3 以下时自动隐藏**；折叠状态与描述显隐是**个人偏好存浏览器、不进工作流文件**；而组结构本身**存进工作流**。（https://docs.n8n.io/build/understand-workflows/workflow-components/canvas-groups ）
- **n8n 有一份官方《UX guidelines》，是「节点设计指南」的稀缺实物**（做验证过的社区节点必须遵守）：凭证一律密码框；每个资源尽量配齐 CRUD（Create/Upsert/Delete/Get/Get Many/Update）；能用 Resource Locator 就用，默认给「From list」；**与既有节点保持 UX 一致**；接口返回 >10 个字段就加 `Simplify` 布尔参数；**节点名用 Title Case，动作名与描述用 Sentence case**；术语跟服务自己的 UI 走而不是跟 API 文档走；不用技术黑话；占位符以 `e.g.` 开头。（https://docs.n8n.io/integrations/creating-nodes/build/reference/ux-guidelines ）

**Blender —— 节点解剖学最细**
- 节点构成：**Title（双击改名，左侧折叠开关，快捷键 H）/ Preview（结果缩略图浮层）/ Sockets（彩色小圆点，未用的可 Ctrl+H 隐藏）/ Properties（在输出之下、输入之上）**。输入在左下、输出在右上。（https://docs.blender.org/manual/en/latest/interface/controls/nodes/parts.html ）
- **Socket 形状编码数据结构**：圆=动态/多类型、矩形=单值、菱形=field、四宫格=grid、三横线=list、省略号=可接多个输入。**形状是与颜色正交的第二条编码通道。**（同上）
- 布局辅助：**吸附到网格**（默认关，可开关，或变换时按住 Ctrl 临时吸附）；**Auto-Offset**——把一个节点拖到已有连线上时，自动把左右节点推开让位（按 T 切换推开方向）。**这两条是「拖拽体验」的直接可抄项。**（https://docs.blender.org/manual/en/latest/interface/controls/nodes/arranging.html ）
- 大图导航：**`Ctrl+F` Find Node**，可按 节点名 / socket 标签 / **告警消息** / socket 值 搜索，命中后自动平移居中并高亮。还有 `Shift+L` Select Linked From/To（按连通性扩选）、`Shift+G` 按类型/颜色/前后缀 分组选择、`Shift+]/[` 在同类型节点间循环跳转。**「按告警消息搜节点」对调试大图极有用。**（https://docs.blender.org/manual/en/latest/interface/controls/nodes/selecting.html ）
- 还有 **Frame 节点**（框住一组节点，类似 n8n 的 Canvas Group）与 **Node Groups**（子流程）。（https://docs.blender.org/manual/en/latest/interface/controls/nodes/parts.html ）

**Unreal Blueprints —— 端口语义的清晰范本**
- 左侧引脚=输入，右侧=输出。引脚分两类：**执行引脚（execution pin，管流程）** 与 **数据引脚（data pin，管数据，强类型、只能连同类型）**。两者都遵循「**未接线时描边空心，已接线时实心**」——**一眼看出哪些引脚空着**。（https://dev.epicgames.com/documentation/en-us/unreal-engine/nodes-in-unreal-engine ）
- 交互：**从引脚拖线到空白处，弹出「只列出与该引脚类型兼容的节点」**；右键空白处则列出全部节点。（同上）
- 类型不同但可转换时，拖线会**自动插入一个 autocast 节点**，并在悬停时用 tooltip 说明兼容性。（同上）

**Dify —— 执行语义与调试**
- **串行 vs 并行**：串行时每个节点能读链上任意前序变量；**并行分支之间互相读不到变量，但汇合后下游能读到全部分支**。单条执行路径上限 **50 个节点**（`MAX_TREE_DEPTH` 可调）。（https://docs.dify.ai/zh/self-host/use-dify/build/orchestrate-node.md ）
- 调试：**任何节点可单独测试**（在设置面板给测试输入，不跑全流程）；跑完点「上次运行」看输入/输出/耗时/错误；**逐步执行时输出缓存进变量检查器，且缓存变量可直接改**，从而不必重跑上游就能测下游对新数据的反应。**「变量检查器可编辑」是极实用的调试交互。**（https://docs.dify.ai/zh/self-host/use-dify/debug/step-run.md ）
- 节点可跨工作流、跨 Dify 实例复制粘贴，配置随节点走，但**变量、集成、知识库这类「周边资源」在目标位置重新解析**。（https://docs.dify.ai/zh/self-host/use-dify/build/orchestrate-node.md ）

## 三、大图与自动布局（含「有环死循环」的正解）

- **React Flow 不提供任何布局算法**，官方只做选型：**Dagre**（支持动态尺寸与子流程，但不支持边路由）、**D3-Hierarchy**（只适合单根树，且强制所有节点同尺寸）、**D3-Force**（物理布局，迭代式，大图每帧计算很贵）、**ELK**（最可配置，也最复杂，且是异步的）。官方原话推荐「要整理成树就用 dagre」，并提醒 **dagre 有个未解决 issue：子流程内节点连到外部节点时布局会出错**。（https://reactflow.dev/learn/layouting/layouting ）
- 边路由另说：官方 Pro 例用 **libavoid** 绕开节点算路径；社区有 **react-flow-smart-edge**。（同上）
- **有环怎么办（关键）**：**dagre 自己是环安全的**。它布局前先跑 `acyclic.run`：用 **greedy 反馈弧集**（Eades–Lin–Smyth 启发式）或 **DFS** 找出「删掉就能破环」的边，把这些边**移除、反向重新加入**并打标 `reversed: true`，布局结束再 `undo` 把方向还原。**所以正确做法是「先破环，再分层」，而不是在有环图上直接 BFS。**（源码：https://github.com/dagrejs/dagre/blob/master/lib/acyclic.ts 、https://github.com/dagrejs/dagre/blob/master/lib/greedy-fas.ts ）
- ProductFlow 的死循环正是**跳过了这一步**：它用 BFS 队列但从不递减入度、也没有 visited 集合，环上节点被无限重新入队（详见 `plans/调研-ProductFlow-代码可借用点.md` 第三节 4）。**修法三选一**：① 直接用 dagre/elkjs（已内置破环）；② 自写 Kahn 拓扑排序时**必须**「出队即递减后继入度 + visited 去重 + 剩余节点非空即判定有环」；③ 先用 DFS 三色标记检测环并提示用户，拒绝布局。
- 另一个更现代的选项：**d3-dag** —— TypeScript 优先的 DAG 布局，自称是 **dagre 在 React Flow 里的 drop-in 替代**，包体积「只有 elkjs 那 ~500KB 转译 Java 的一小部分」，支持 `quality: fast/medium` 预设；**注意它要求每个节点必须有正的 width/height**（无尺寸节点会抛错），且不支持 compound graph（`setParent`）。（https://github.com/erikbrinkman/d3-dag ）
- 分组/折叠的两种实现路径：**React Flow 的 Sub Flow**（`parentId` + 子节点坐标相对父节点 + `extent:'parent'` 限制不能拖出；**父节点必须排在子节点之前**；**挂在有父节点上的边会渲染在节点之上**，可用 `zIndex` 调）；（https://reactflow.dev/learn/layouting/sub-flows ）或 **n8n/Blender 的「框选成组 + 可折叠」**（对使用者更轻，不需要真的建父子关系）。

## 五、运行时可视化（对照我们已定的 ProductFlow 做法）

- **状态枚举建议**：`idle / queued / running / success / failed`，再补一个 **`missing`（依赖缺失）**——ComfyUI 的 Missing 状态证明「环境缺件」是独立状态，不应混进 failed。（https://docs.comfy.org/basic-concepts/nodes ）
- **官方状态组件形状**：`NodeStatusIndicator` 的 status ∈ `success/loading/error/initial`，loading 有 `border`（转圈描边，默认）与 `overlay`（整块蒙层 + 动画 spinner）两变体。**我们可扩成 success/loading/error/queued/initial 五态，沿用「包装器 + 变体」结构。**（https://reactflow.dev/ui/components/node-status-indicator ）
- **进度与排队**：ProductFlow 已有「排队位置 + 进度 + 失败原因 + 取消 + 重试」（见 `plans/调研-ProductFlow-代码可借用点.md` 二节表格）。业界补充两条语义：**失败后可选「自动重试」（n8n `Retry On Fail`）**，以及**失败可按「继续 / 带错误继续」下传**（n8n `On Error` 三态）。（https://docs.n8n.io/build/understand-workflows/workflow-components/work-with-nodes ）
- **单步调试**：Dify 的「单节点测试 + 上次运行详情 + 可编辑的变量检查器」值得排进路线图——它是「大图调试」的性价比最高的一项。（https://docs.dify.ai/zh/self-host/use-dify/debug/step-run.md ）
- **画布级性能开关**：ComfyUI 的「低质量渲染缩放阈值 0.6」——缩远了就降级渲染，**这是大图流畅度的关键一招**。（https://docs.comfy.org/interface/settings/lite-graph ）
- **无障碍**：RF 的 Tab 遍历 + Enter 选中 + 方向键移动 + 聚焦自动平移 + `ariaLabelConfig` 中文化，是**零成本可得**的，建议直接开。（https://reactflow.dev/learn/advanced-use/accessibility ）

## 六、对我们的落地建议（推断，未验证）

1. **节点骨架**：抄 `BaseNode` 的四段式（Header / HeaderTitle / Content / Footer）+ `NodeStatusIndicator` 包装器 + `NodeAppendix`（放依赖缺失徽标、运行耗时）。这与我们「节点必须声明依赖」天然契合——**依赖缺失直接进 Missing 状态与 Appendix 徽标**。
2. **端口**：颜色编码**按我们自己的适配器类型分**（shell / agent / http / builtin 四色），连线同色；分支型 Handle（if 的 true/false、loop 的 iterate/done）**沿用现有 schema 的 Handle id，不要改**（`skills/dsh-node-flow-skill/references/workflow-schema.md`）。形状编码可用于区分「数据流」与「控制流」（参考 UE 的执行引脚 vs 数据引脚）。
3. **自动布局**：**不要自己写**。用 dagre（环安全、体积小）或 d3-dag（更现代）。若必须自研，先破环再分层。
4. **大图**：先做「框选成组 + 可折叠」（n8n 式，实现轻），**子流程（Sub Flow）留到真有必要时再做**——它会带来父子坐标、zIndex、边渲染层级的额外复杂度。
5. **连线降噪**：默认 Spline，但**提供「隐藏所有连线」开关**（ComfyUI 的定稿降噪做法），以及「拖线时高亮候选节点 + 自动吸附插槽」。
6. **状态与错误**：把 n8n 的 `On Error` 三态（stop / continue / continue-with-error）作为**节点级配置**纳入我们的执行语义——这比「失败就整体停」更适合生产。
