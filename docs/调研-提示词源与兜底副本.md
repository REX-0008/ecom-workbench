# 调研 · 提示词源与兜底副本（2026-10-25）

> **起因**：契约 AZ。内容板块的「提示词库」要从外部源拉提示词（计划 §三 Step 6）。
> 外部源会挂——仓库改名、删库、网络不通。所以每个源要在代码里留一份**截断过的兜底副本**。
>
> **这份文档解决三件事**：① 选了哪几个源、凭什么选；② 每个源的实测与许可；③ 以后怎么更新副本。
>
> **已核实** = 本次实测（命令与输出见 §五）；**未核实** = 只见到文档/仓库页说明，标出来。

---

## 一、先说清楚：这个「提示词库」不是现有「提示词」板块

两个都留，职责分开（用户 2026-10-25 定）：

| | 现有「提示词」板块 | 内容板块的「提示词库」 |
|---|---|---|
| 面向什么 | **改写**：把一段提示词按模板风格改写一遍 | **找素材**：生图 / 生视频用的提示词素材 |
| 内容 | 62 个固定模板（优化 / 迭代 / 提取 / 图像 / 评估） | 外部提示词源（GitHub 上的 JSON 集合） |
| 数据在哪 | 代码里（`templates/*.ts`） | 网络拉取，缓存到 `prompt-cache/`，代码里另留兜底副本 |
| 能不能加 | 要改代码 | 源可自己填 |

**一句话**：板块是「加工厂」，提示词库是「素材仓库」。

## 二、选了这 5 个源

它们的上游都写在同一个索引仓下（`yukkcat/image-prompts`），每个源一份 JSON。
**注意：索引仓只是「转发」，真正的作者是各自仓库**，所以许可要逐个核，不能只看索引仓。

| # | 源 id | 显示名 | 许可 | 内置条数 | 上游条数 | 是否截断 |
|---|---|---|---|---|---|---|
| 1 | `awesome-gpt-image` | Awesome GPT Image | **MIT** | 53 | 53 | 否 |
| 2 | `awesome-gpt4o-image-prompts` | Awesome GPT-4o | **MIT** | 76 | 76 | 否 |
| 3 | `youmind-gpt-image-2` | YouMind GPT Image 2 | **CC BY 4.0** | 126 | 126 | 否 |
| 4 | `youmind-nano-banana-pro` | YouMind Nano Banana Pro | **CC BY 4.0** | 129 | 129 | 否 |
| 5 | `banana-prompt-quicker` | Banana Prompt Quicker | **MIT** | 200 | **323** | **是，削掉 123 条** |

### 选这五个的理由

1. **许可清楚**：三个 MIT、两个 CC BY 4.0。**CC BY 4.0 要求署名**，所以界面上展示这几条时要带作者与来源（上游每条本来就有 `author` 与 `sourceUrl` 字段，照显示即可）；
2. **条目够用**：合计 584 条，覆盖摄影写实、插画、电商图、模型特定风格等；
3. **有 tags 可筛**：五个源的字段完全一致，都有 `tags` 数组（如「摄影与照片级写实」、作者名），可以按标签筛；
4. **中文占比高**：`awesome-gpt-image` 53/53 全中文、`banana` 193/200 中文、两个 YouMind 源 125/126 与 128/129 中文。**`awesome-gpt4o` 只有 38/76 是中文**，其余英文——这是它唯一的短板。

### 被排除的三个，以及为什么

| 源 | 许可 | 条目 | 排除理由 |
|---|---|---|---|
| `davidwu-gpt-image2-prompts` | **没有 LICENSE 文件** | 494 | **没有许可就不能复制进代码库**。仓库根目录只有 `README.md` / `index.html` / `prompts.json` / `prompts_backup.md` / `images/`，**没有 LICENSE 也没有 COPYING** |
| `freestylefly-gpt-image-2` | MIT（35002 星） | 541 | 许可没问题、条目最多，但按 200 条上限只能留不到四成，性价比不如前五个；**要加随时可以加**（见 §六） |
| `youmind-*` 之外的第三方 | — | — | 没入选的三个已经覆盖了「写实 / 插画 / 电商 / 模型特定」四类 |

⚠️ **一条要说清的**：`YouMind-OpenLab` 两个仓库在 GitHub API 里报的许可是 `NOASSERTION`（识别不出标准名）。我去读了仓库里的 `LICENSE` 文件原文，**内容是 CC BY 4.0**（1364 字节，开头写着 "Creative Commons Attribution 4.0 International License (CC BY 4.0)"）。所以按 **CC BY 4.0** 处理，不按「无许可」处理。**这个区别要紧**：无许可不能用，CC BY 4.0 能用但要署名。

## 三、每个源的数据结构（五个源完全一致）

顶层是**数组**，每条是对象，字段如下（照抄上游，我们不翻译不改名）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 上游给的稳定 id，形如 `awesome-gpt-image:ad0d0535caecb924` |
| `sourceId` | string | 属于哪个源 |
| `title` | string | 标题（一行） |
| `prompt` | string | **提示词正文**——唯一要复制给模型的那段 |
| `description` | string | 补充说明，可能是空串 |
| `coverUrl` | string | 效果图地址（GitHub 附件链接），可能是空串 |
| `referenceImageUrls` | string[] | 参考图地址列表 |
| `tags` | string[] | 可筛的标签（题材 / 作者） |
| `author` | string | 原作者（**CC BY 的署名就用它**） |
| `sourceUrl` | string | 原帖地址 |
| `createdAt` | string | 上游时间字段，可能是空串 |
| `imageMode` | string | 上游图模式字段，可能是空串 |
| `imageModel` | string | 上游标注的模型名（如 `gpt-image-2`） |

**实测确认**：五个源的字段集合**完全相同**（用脚本取并集比对，见 §五）。所以代码里只声明一份类型，不为每个源各写一个。

## 四、为什么留 200 条 / 300 KB 上限

**因为这份副本要跟代码一起打包。**

它不能放数据目录——放数据目录会在换机、清缓存、重装插件时丢，那就失去「断网也能用」的意义了。既然进代码，就要管体积：

- 现在五个文件合计 **930 KB**（未压缩）；
- 上限 200 条 / 300 KB 是**两个都要满足**，哪个先到就按哪个削；
- 实削结果：只有 `banana-prompt-quicker` 触发（323 条 → 200 条，244.3 KB）。

**为什么不是 100 条或 500 条**：100 条太少（不够翻），500 条会让单文件到 600 KB 以上（五个源合计 3 MB 进打包产物，太重）。200 条是「够翻一翻」与「不拖累打包」之间的取值。

⚠️ **削掉的部分要去哪里看**：上游地址本来就在 `url` 字段里，运行时网络通了就拉全量。**内置副本只是断网时的下限，不是上限。**

## 六、这份副本怎么更新

### 6.1 什么时候该更新

- 上游条目明显变多（运行时能从网络拉到全量，发现比内置的多很多）；
- 上游改结构（字段改名、加字段）——这时**代码里的类型也要跟着改**；
- 某一源彻底挂了，要换源。

### 6.2 更新步骤（照抄可跑）

**第一步：拉原文到临时目录**（不进仓库）

```
mkdir F:\AGENTS\agent-chat-dsh\tmp\prompt-raw
```

然后逐个源下载（把 `<源id>` 换掉）：

```
$base="https://raw.githubusercontent.com/yukkcat/image-prompts/main/dist/sources"
Invoke-WebRequest -Uri "$base/<源id>.json" -OutFile "F:\AGENTS\agent-chat-dsh\tmp\prompt-raw\<源id>.json"
```

**第二步：裁剪**（最多 200 条、最多 300 KB，只截断不改结构）

裁剪脚本是临时的，用完即删，思路是：读原文数组 → 取前 200 条 → 若字节数仍超 300 KB 则继续从尾部削减 → 写进 `src/client/workbench/prompt-sources/`。
**关键纪律：只做切片，不改任何一条的内部字段。** 改了字段就跟上游对不上账了。

**第三步：改 `index.ts` 的条数**

`prompt-sources/index.ts` 里每个源有两个数：

- `count` —— **不要手写**，它读的是 `entries.length`，会自动跟随文件；
- `upstreamCount` —— **要手改**，写上游原文的条数（用 `Invoke-WebRequest` 拉一次数出来）。

`count` 与 `upstreamCount` 不等，就表示这份是截断过的。

**第四步：校验**

跑 §五 的两条命令，确认：能解析、≤300 KB、≤200 条、退出码 0。

**第五步：跑类型检查**

```
$env:DSH_HOME="F:/AGENTS/agent-chat-dsh"
npm run check:client
```

### 6.3 加一个新源要动三处

1. 把裁剪好的 `.json` 放进 `prompt-sources/`；
2. `index.ts` 顶部加一行 `import`，数组 `BUILTIN_PROMPT_SOURCES` 里加一条（填 `id` / `name` / `url` / `homepage` / `license` / `upstreamCount`）；
3. 本文档 §二 的表里补一行。

⚠️ **加源之前必须先核许可**。没有 LICENSE 文件的仓库不能用（代码公开不等于给了复制权）——这是硬门槛，不是谨慎。
