# 调研：节点自展开 / 节点内联设置 / 节点显示内容（2026-10-08）

> 状态：调研完成（2026-10-08）· 面向 ecom-workbench 工作流画布（React Flow 12.12.0）
> 纪律：star / 许可均为实际查询所得（GitHub API + npm registry），非估计。未核实项已单列。

## 1. 一句话结论

**没有现成库能直接满足这套需求，但业界三个成熟项目把它们逐个做全了——模式已验证可行，我们要自己实现。**

- **现成的（npm 可直接装）**：React Flow 自带的 `NodeToolbar`（节点旁工具条）、`NodeResizer`（节点改尺寸）、以及"自定义节点组件"这个机制本身。这些是**零件**。
- **要自己写的**：两态节点（折叠/展开）、节点内容槽（图片/文本预览）、运行进度可视化、流程推进自动折叠——**没有 npm 包**（npm 全库检索 `react-flow node inspector / inline edit / node expand` 均无对应包，见 §6）。
- **可参考的实物**：**Langflow（MIT，React Flow 生态，最贴近）**、**n8n（节点运行按钮 + 状态）**、**ComfyUI（节点预览 + 进度 + 折叠，GPL 只可看不可抄）**。

## 2. 这类模式的业界叫法与代表实现

| 业界叫法 | 指什么 | 代表实现 | 与我们需求对应 |
|---|---|---|---|
| **Node inline parameters / 画布内联参数** | 常用设置直接画在节点上，不弹面板 | Langflow（`isCanvasVisible` 过滤） | 特征 1、2 |
| **Advanced / 高级参数折叠** | 标 `advanced` 的参数不上画布，另开面板 | Langflow `parameter-filtering.ts` | 特征 2 |
| **Node preview / 节点预览** | 节点上直接显示业务产物（图片/文本） | ComfyUI `useNodePreviewState`、`TextPreviewWidget` | 特征 3 |
| **Node progress / 节点级进度** | 进度条/进度文字长在节点上 | ComfyUI `useNodeProgressText`、n8n `CanvasNodeStatusIcons` | 特征 4 |
| **Collapsed node / 折叠节点** | 折叠态只显示标题+概览 | ComfyUI `isCollapsed` 门控预览；n8n 有独立 `NodeSettings` 面板 | 特征 2、5 |
| **Node toolbar / 节点运行按钮** | 节点悬浮工具条上带运行键 | n8n `CanvasNodeToolbar.vue`（`emit('run')`）、React Flow `NodeToolbar` | 用户原话"节点是不是该有运行按钮" |
| **NDV（Node Detail View）** | n8n 的说法：点开节点进详情视图改全套参数 | n8n `features/ndv/` | 特征 1 的"展开"侧 |

**结论：这是 node-based editor 的公认交互范式，不叫某一个专有名词，而是"inline params + collapsed/expanded + node preview + node progress"的组合。**

## 4. 逐条对照用户要的 5 个特征

| # | 用户要的 | 现成吗 | 谁做全了（证据） | 我们要写什么 | 工作量 |
|---|---|---|---|---|---|
| 1 | **节点内联显示设置**（不弹悬浮框） | ⚠️ 半现成 | Langflow：`RenderInputParameters/index.tsx` 把参数按 `isCanvasVisible` 直接画在节点上 | 节点里渲染表单控件（受控 input/select），把 param 写回 zustand | **中**（2–3 天） |
| 2 | **两态节点**：折叠=概览／展开=全套 | ⚠️ 半现成 | Langflow：`advanced===true` 的参数不上画布，另进面板；ComfyUI：`isCollapsed` 参与门控 | 节点加本地 `expanded` 态；折叠渲染摘要、展开渲染表单；高度变化后调 `useUpdateNodeInternals()` | **小**（1 天） |
| 3 | **节点显示业务内容**（图片节点显示图片） | ❌ 无 npm 包 | ComfyUI：`useNodePreviewState.ts`（`previewUrls / latestPreviewUrl` 从 `nodeOutputStore` 取图）；`ImagePreview.vue` | 在 `NodeDef` 加"内容槽"概念；图片类节点渲染 `<img src=...>`，从运行结果取 URL | **中**（2–3 天） |
| 4 | **运行时节点自己显示进度/状态** | ❌ 无 npm 包 | ComfyUI：`useNodeProgressText.ts` 把进度文字作为 widget 挂到节点；n8n：`CanvasNodeStatusIcons.vue` | 已有六态 `NodeState` + `progress` 字段（model.ts 已定义！），只需在节点上做视觉；可加进度条 | **小**（1–2 天，基建已有） |

## 5. 推荐方案

### 首选：自己实现，抄 Langflow 的结构（MIT，可合法借鉴）

**为什么不是直接用一个现成项目**：Langflow / n8n 是**整套应用**，不是可嵌入的节点组件库。它们的节点组件深度耦合自己的 store、API、i18n，抽出来比自己写还慢。但**结构和判定逻辑值得 1:1 照搬**。

**具体做法（按依赖顺序）**

1. **给 `NodeDef` 加"内容槽"字段**（改 `workflow/model.ts`）
   在 `NodeDef` 上加 `preview?: 'image' | 'text' | 'none'`、`inlineParams?: string[]`（哪些参数上画布）、`advancedParams?: string[]`（哪些进展开区）。
   → 这正是 Langflow 的 `advanced` 轴，语义已验证。

2. **节点组件做两态**（改 `v1-NodeCard.tsx`）
   本地 `useState` 存 `expanded`，不写进节点数据（避免持久化噪音）。
   - 折叠态：现有渲染（执行方 + 标题 + 端口 + 状态条）**再加一行摘要**（如"用 gpt-4 · 12 字"）
   - 展开态：标题下方插入 `inlineParams` 的表单控件 + 内容槽（图片预览）
   - **关键坑**：展开改变节点高度后，必须调 `useUpdateNodeInternals()` 通知 React Flow 重算 handle 位置（Langflow 同款做法）。

3. **内容槽单独一个组件**（新建 `v1-NodePreview.tsx`）
   参照 ComfyUI 的 `useNodePreviewState`：从运行结果里取该节点产出的首个图片/文本 URL，折叠态只显示缩略图或首行文字。

4. **进度可视化**——**基建已就绪**，只需画
   `model.ts` 已有六态 + `progress?: string`。运行中在状态条加进度条（`running` 时铺满宽度的动画条），失败时显示错误摘要。

5. **自动折叠**
   在运行状态批量更新处（派发器回调）加规则：`success` 的节点自动置 `expanded=false`，`running` 的自动置 `true`。注意这是**交互态**，别写进工作流数据文件。

6. **运行按钮**
   用 React Flow 的 `NodeToolbar`（v12 已在主包内）挂在选中节点旁，或直接**画在节点卡片右上角**——n8n 用的是后者（`CanvasNodeToolbar` 是节点内元素，不是浮层）。**推荐节点内元素**，与"不用悬浮框"的诉求一致。

**不建议**：把 Langflow / n8n 的代码整段搬进来（耦合太重、许可风险、维护负担）。
