# PowerShell 写文件把中文编码写坏

## 症状

源码文件里的中文标点变成 `?`，例如：

```diff
-/** 画布布局：ELK 自动分层 + 兜底网格 + 尺寸测量。
+/** 画布布局：ELK 自动分层 + 兜底网格 + 尺寸测量�?
```

**构建照样通过、测试照样全绿** —— 坏的只是注释和文案里的标点，
类型检查和运行时都不受影响。所以这类损坏**只能靠专门的扫描发现**。

## 成因

用 PowerShell 的 `Set-Content` / `Out-File` 回写文件时，
它按**系统默认编码**（简体中文 Windows 上是 GBK / code page 936）写盘，
而源文件是 UTF-8。于是：

- 原文里的 `。`（UTF-8 三字节）被按 GBK 解读 → 得到乱码 → 再用 GBK 写回 → 变成 `?`
- 单个坏字节还会**吃掉后面一个正常字符**，表现为「少了一个字 + 多个问号」

本次实测：`。` `」` `——` 这三类标点最容易中招。

## 什么场景会踩

最容易发生在**「改文件验证测试断言」**这类往返操作上：

```
读原文 → 用 PowerShell 替换一处 → 跑测试 → 还原
```

这次就是为了验证 7 条新断言「改回去会不会失败」，
用 `Get-Content` + `-replace` + `Set-Content` 往返了 5 个文件，
**5 个全被写坏，而且当场没发现**（测试全绿），直到下一个会话打开文件才暴露。

## 规避

**核心规矩：不要在 PowerShell 里回写要被程序读取的文本文件。**

| 要做的事 | 用什么 |
| --- | --- |
| 改源码、注释、文档 | `edit` / `write` 工具（它们保证 UTF-8） |
| 批量改、生成文件 | **Node 脚本**（`readFileSync` / `writeFileSync` 默认 UTF-8） |
| 真要用 PowerShell 写 | 显式指定编码：`Set-Content -Encoding utf8NoBOM` |

**必须用 Node 的一个理由**：脚本本身也是要被人看的，
而且 Node 的读写默认就是 UTF-8，不用每次记得加参数。

## 怎么发现

**扫描全仓**（跑一次就能知道有没有踩）：

```js
import { readFileSync } from 'node:fs'
const buf = readFileSync(file)
try { new TextDecoder('utf-8', { fatal: true }).decode(buf) }
catch { console.log('坏: ' + file) }
```

把它当**提交前的检查项**之一。本次修完已确认全部源文件合法。

## 怎么修

**不要用 PowerShell 修**（会再坏一次）。用 Node 脚本：

1. `git show <干净提交>:<路径>` 取出干净的原文；
2. 把这一轮**内容正确的改动**重新施加回去（用 `replace`，并断言命中次数恰好为 1）；
3. `writeFileSync` 写盘。

本次的做法写在提交说明里；关键点是**逐个 patch 断言命中数**，
一旦某个 patch 在干净原文里匹配不到或匹配到多次，立刻中止——
否则会静默改错地方。

## 一个连带损失

本次损坏后，修复时我按「干净原文 + 重放改动」重建，
**漏了两处**（`nowheel` 类名、一个已删的 import），
说明「重建」不能只靠记忆，**重建完必须跑一遍断言核对**。
当时的 `dom-render` ⑬ 段立刻抓出来了（`参数区带 nowheel` 变 ✗），这正是它存在的价值。
