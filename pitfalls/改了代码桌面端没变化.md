# 改了代码但桌面端没变化（部署目录是一份拷贝）

## 症状

代码改了、`npm run bundle` 也跑了、`npm run test` 全绿 —— **但界面上就是没有新东西**。

本项目已踩过两次。第二次的具体表现（2026-10-15）：

> 打开刚生成的「一键下载」工作流 → 「已加载 0 个节点，但缺 2 种节点类型（flow.workflow）」

新节点的定义**确实**在源码里、也**确实**进了构建产物，但桌面端读的是**另一份文件**。

## 成因（实测）

| 事实 | 出处 |
| --- | --- |
| 插件在 profile 里是 **`file:` 依赖** | `profiles/desktop/package.json` 的 `@our/ecom-workbench: file:../../my-dsh-plugins/ecom-workbench` |
| 那个 profile 用 **`nodeLinker: hoisted`** | `profiles/desktop/pnpm-workspace.yaml` |
| 两者合起来 = pnpm 把插件**复制**一份 | 不是符号链接 |

所以「源码目录的 `lib/`」与「部署目录的 `lib/`」是**两个不同的文件**：

```
源码  <仓库>/lib/client.js                        ino=3659174698027428  size=3818442 ← 刚构建
部署  profiles/desktop/node_modules/@our/ecom-workbench/lib/client.js
                                                  ino=4503599627979835  size=3766226 ← 桌面端在读（旧）
```

**判据**：两个 inode 不同 + 大小不同 = 确实是两份拷贝。
（`nodeLinker: hoisted` 下 `pnpm install` 就是复制，不是链接 —— 这一点在
`plans/工作流基础-2026-10-12-02-节点目录化与浏览器层.md` 的 Step 2.5 里已核实过。）

⚠️ **注意区分**：同一个 profile 里另外几个自研插件（`context-panel-write` /
`dsh-todo-board` / `prompt-modules`）写的是 **`link:`**，它们**没有这个坑** ——
改完直接生效。只有 `@our/ecom-workbench` 与 `@our/workbench` 是 `file:`。

## 修法

`npm run bundle` 现在会**自动同步**到部署目录（`scripts/deploy.mjs`，接在
`copy-runtime.mjs` 后面）。也就是说：**只跑 `npm run bundle` 就够了。**

同步完还要让运行中的桌面端重新读：

| 改了什么 | 怎么生效 |
| --- | --- |
| 客户端（`src/client/**`） | **刷新页面** |
| 宿主半（`src/index.ts` / `src/workflow/**` / `src/nodes/**`） | **重启桌面端** |

## 为什么 `deploy.mjs` 不是「绕过 pnpm」

与 `scripts/install-browser-deps.mjs` 同一套理由：

- 它只是**提前做了 `pnpm install` 本来要做的事**（同一位置、同一结果）；
- `pnpm install` 会重写整个 `node_modules/`，而那是**运行中的桌面端正在用的目录**
  （红线：单写入者）—— 而要求用户退出桌面端 = 同时关掉 AI 会话，是死循环；
- `deploy.mjs` 只覆盖**我们插件自己那几个产物文件**，不动别的包，
  所以能在桌面端运行时做。

`deploy.mjs` 里有一条自检：**若发现部署目录与源码是同 inode（即哪天改成 `link:` 了），
就直接退出、不做任何拷贝** —— 那时继续拷反而会搅乱（link 模式下两边本来就是同一份）。

## 相关的另一个坑（同一族，别混淆）

`src/nodes/browser/driver.mjs` 是**运行期脚本**，靠 `scripts/copy-runtime.mjs`
复制进 `lib/`。**改了它必须 `npm run bundle`** —— 不复制的话部署目录里还是旧脚本，
真机表现同样是「改了没生效」。现在这两步都串在 `bundle` 里了。

## 怎么快速自查

```powershell
# 两个 inode 是否相同（相同 = 链接，不同 = 两份拷贝）
node -e "const fs=require('fs');const s=fs.statSync('<仓库>/lib/client.js');const d=fs.statSync('<profile>/node_modules/@our/ecom-workbench/lib/client.js');console.log(s.ino===d.ino?'同一份':'两份拷贝')"

# 部署目录里到底有没有某个新东西
node -e "const t=require('fs').readFileSync('<profile>/node_modules/@our/ecom-workbench/lib/client.js','utf8');console.log(t.split('flow.workflow').length-1)"
```
